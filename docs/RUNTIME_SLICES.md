# 当下切片与夜间拼图

2026-09-29，用户明确“runtime 先保存当下轨迹等切片，不立刻处理复杂逻辑，深夜复盘再把今天形成完整落地拼图”。本次接入已有日构建，维持 [完整存在架构](EXISTENCE_ARCHITECTURE.md) 的三部分划分。

## 白天留下什么

`KernelLogic` 在一轮完成后调用 `RuntimeSliceLogic.Capture`，直接保存同次 Agent 已给出的当下状态、关注、轨迹、生活描述及结构化发言者来源；不新增模型请求，不做认知抽取、人格评分或身份重写。原始对话和执行回执继续使用原有存储。

`runtime_slices` 每轮一个稳定 ID，与触发 Moment / OperationalEvent 对应。时刻和可见性由真实来源确定，模型不能写入。插入只追加，同轮重放不覆盖最初内容；跨日、更新最新 runtime 或更新滚动轨迹都不会删除旧片段。

切片记录的是**当时如何感受与理解**。`new_fact` 是便签，`scene` 是文字场景，活动描述不等于执行成功；切片不直接变成外部事实证据。短期接续所需的最新状态照常更新，不等待深夜才回应当前感受或明确约定。

## 深夜怎样落地

沿用 04:00（+08:00）记忆日边界，自动和手动日构建共用入口，不另建白天后台循环。

- **2026-10-12起，拥挤日先入围再成稿。** 同日同环境同可见性超过12条切片时，不再先写各段长文。按时间分批（至多80条/16000字），每批合并同一事件的重复提及，提名1～6件变化，用目标80字、建议120字以内的目录描述及本批来源编号表达；2026-10-21起控制全部候选描述合计720字，单项略超120不再独立失败。程序仍检查条数、目录总预算和真实来源。少量切片沿用下述兼容路径。
- 候选目录再全局选择最多6件事件；超过单批24项/8000字时分批选择并继续比较胜者。入围编号由程序映射回原件，完整依据总预算16000字，不按出现频率或时间位置机械截取。模型选择应兼顾决定、转折、未决事项、反证及结果。程序只能验证引用和预算，语义重要性仍由模型判断。
- 只加载入围事件的完整切片，生成一篇约500字、最多1000字的回望，不拼回旧长段。未入围原始切片与事件仍保留、可查证；整日来源记录表示已处理范围，不表示每件事都写入摘要。认知阶段继续独立覆盖完整原始经历，不使用此摘要入围结果过滤认知证据。
- 不超过12条的少量切片及旧分段兼容路径：每批至多80条/16000字，按原切片写段落，按时间用空行接成正文；合并不超过1000字直接发表，超过时精简一次到500字目标，仍超1000字就不发表，已写各段保留。所有路径都不截断保存正文。
- 随后的认知阶段只看这一批的原文、当时的感受短句，以及这一批对应的事件短句。已有认知只带编号、对象、领域和用途，用来选择修订目标；范围、例外和整天事件细节留在库里，不反复贴进请求。私密与公开分开整理；公开不能借私人原文或身份卡形成结论。
- 认知原文与切片一起计入每批 24000 字 / 200 条预算，依次覆盖所有可处理经历。超大单条报错保留，不能静默略过后标记整天完成。
- 身份复盘先按slot选择有效、可见且非人工固定的认知，每卡最多6条/6000字完整依据；候选超过预算时按上述目录方式筛选，移除原先任取前40条的限制（读取图上限仍为5000条）。目录保留对象、完整认识、范围、例外和变化时间；成稿保留入围认知完整对象。已形成的当天主观回望只作为背景，不再重复注入全天事件细节和实时便签。旧摘要仍供融合，没有变化可不更新；同slot引用、原有300字目标/600字边界及固定保护保持。

每个环境一天只有一篇供阅读和召回的成稿；分段是整理材料，不累加为页面正文。私密和公开环境各自整理，四领域是理解方向。摘要重写、自己再次提起和反复召回都不是新的外部证明。

## 失败、重启与并发

### 2026-10-22：核心完成之前的批次恢复（0.1.57）

事件观察先保存结构合格的草稿，超过80字的摘要只对相应字段进行一次定向重写，合格内容和来源不变；仍超限或修复无效则停止，恢复只续短句。认知自身关联在有效来源、目标、环境与关系校验后跳过，不写自环、证据或权重，同批其他有效操作可正常提交。

事件批与标签激活、单条细节、认知证据批分别保存进度，结果与进度在各自同一主库事务提交，进程中断恢复跳过已完成批次。检查点绑定完整来源集合、原文、角色、当时切片与身份；事件/细节正文被修改或生成期间引用已变化时停止复用。来源超过256条仍分块完整读取。已有核心完成后的迟到来源建立独立代次，后续身份与排序继续使用0.1.55检查点。

旧版没有批次指纹的部分事件不能安全推断完整原始范围，因此升级后保留并拦住整日重复写入，须备份、核对后另行恢复。该保护不把旧失败标记为成功，也不清理或自动重建历史数据。自动暂停、手动预检、引用和可见性规则保持。新增真实Migration临时库/模拟模型回归通过，未部署或调用真实模型；本段取代下方“核心之前尚无批次检查点”的历史边界。

### 2026-10-21：阅读正文待整理与核心失败分开（本地实现）

目录提名按整批720字控制，不因单项122字就额外改写。超过整批预算才将超过建议篇幅的条目合为一次修复请求，保留其余描述与全部来源；持续不合格仍保留检查点并有限停止。下方2026-10-19的逐项120字硬边界为历史行为。

日回望正文的预算失败使用明确的`ReviewProsePendingException`，JSON/引用等错误仍走严格失败路径。新日及已完成日的迟到回望都可明确标记待整理，未成稿切片不清除或假报完成。身份生成先严格验证整批结构及同slot真实引用，再把超限正文合为至多一次定向请求，只提供对应原有引用的完整认知，不回传超长草稿；合格卡和内心部分可提交，超限项保留原有效卡并记录待整理。

核心检查点在事件、细节和认知成功之后保存来源指纹与事件/条目ID，身份与排序分别记录完成。恢复时只请求未完成正文，不重建这些已完成核心结果或重复排序；新增私密来源可继续处理增量，新公开来源必须先整理，不能被私密检查点略过。卡片、认知及原来源被修订时拒绝旧草稿或旧检查点；内心继续使用主体版本保护。身份检查点记录已提交字段，避免续做时再次覆盖合格卡。

迁移状态新增`pending`，表示核心已完成但仍有阅读正文待整理，历史尝试独立保留该状态。手动预检列出并允许续做；自动调度不会仅因这些正文或其待整理切片反复付费重试，后续日期仍可处理。真正结构、引用、网络或来源错误保持`failed`及原暂停保护。不能把`pending`当作整日`done`，也不自动转换既有失败记录。

本次没有重构认知提炼、身份语义综合、单一slot分类、事件合并排序或旧`identity.review`入口。核心检查点之前的事件观察/认知批次仍沿用原有失败流程，尚未增加逐批独立检查点。全解决方案构建、完整ChatCheck/Prompt、实际Migration入口及页面专项通过；过程重启、合格卡不重复写、引用错误不部分提交、生成期间卡片/认知修订、迟到回望与待整理队列已用临时库和模拟模型验证。未调用真实模型、发布、载入本机入口或部署服务器。

## 查看与召回

控制台“身份”页的“当下切片与夜间拼图”按记忆日查看，显示全部切片数量、待复盘数量、当天成稿和最近100片。分段整理材料折叠保留，成稿尚未完成时明确提示。`GET /runtime/slices?day=yyyy-MM-dd` 沿用控制台认证。

日常召回及日终身份复盘使用有效成稿。未进入新成稿流程的旧版历史仍按旧方式保留召回，不在升级时批量调用模型重写历史；重新整理某天时会兼容已有长分段并形成新成稿。

夜间回望接入 `MemoryRecallLogic` 的统一候选预算；只召回与当前查询相关的片段，并标记为主观回望。公开视图只读取本环境回望，私密视图可回望同一主体经历的各环境。回望不会把私人原文自动分享出去，也不能把回望 ID 填作认知引用。
