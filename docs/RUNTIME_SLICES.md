# 当下切片与夜间拼图

2026-09-29，用户明确“runtime 先保存当下轨迹等切片，不立刻处理复杂逻辑，深夜复盘再把今天形成完整落地拼图”。本次接入已有日构建，维持 [完整存在架构](EXISTENCE_ARCHITECTURE.md) 的三部分划分。

## 白天留下什么

`KernelLogic` 在一轮完成后调用 `RuntimeSliceLogic.Capture`，直接保存同次 Agent 已给出的当下状态、关注、轨迹、生活描述及结构化发言者来源；不新增模型请求，不做认知抽取、人格评分或身份重写。原始对话和执行回执继续使用原有存储。

`runtime_slices` 每轮一个稳定 ID，与触发 Moment / OperationalEvent 对应。时刻和可见性由真实来源确定，模型不能写入。插入只追加，同轮重放不覆盖最初内容；跨日、更新最新 runtime 或更新滚动轨迹都不会删除旧片段。

切片记录的是**当时如何感受与理解**。`new_fact` 是便签，`scene` 是文字场景，活动描述不等于执行成功；切片不直接变成外部事实证据。短期接续所需的最新状态照常更新，不等待深夜才回应当前感受或明确约定。

## 深夜怎样落地

沿用 04:00（+08:00）记忆日边界，自动和手动日构建共用入口，不另建白天后台循环。

- 切片按日期、环境和时间分批，每批至多 80 条 / 16000 字。每批只收到本批完整切片，已完成回望由程序按来源时间保存，不再带回后续批次重写。所有原切片分别处理，不只保留最后一份轨迹。
- 模型整理经历、感受变化、关注、关系对象和未解之处；可以没有稳定结论。结果保存在 `runtime_day_reviews`，附完整切片 ID 和触发来源 ID，不直接写人格卡。
- 随后的认知阶段看到预算内的完整原文及其对应切片，逐条引用真实 Moment。私密与公开分开整理；公开不能借私人原文或身份卡形成结论。
- 认知原文与切片一起计入每批 24000 字 / 200 条预算，依次覆盖所有可处理经历。超大单条报错保留，不能静默略过后标记整天完成。
- 身份复盘只从有效认知形成摘要，人工固定内容受保护。回望和认知留在同一长期拼图中，后续通过已有召回进入当下；原切片继续作为来源保留。

一天可以形成多段有次序的拼图，不强制压成一个大段或四条性格标签；四领域是理解方向。摘要重写、自己再次提起和反复召回都不是新的外部证明。

## 失败、重启与并发

正文通常以600～1200字为精炼目标，沿用每段3000字存储上限。超长纠正明确给出实际字数与上限；连续两次仍超长时按完整切片边界对半拆批，最多两层。每批至多两次模型调用，一次原始批次最坏14次；单条、拆分到上限仍异常、结构/类型错误、调用失败或取消均保留未完成原件并走失败路径。正文不截断，原切片不切碎。

每批回望与切片完成标记事务提交；模型失败或提交失败留下待处理片段。重启按待复盘日期补偿，成功批次不再调用模型。日构建后续阶段失败不删除已落地回望，也不清空原切片。整日成功后旧滚动轨迹与今日便签才退出实时区，次日状态不受影响。

已完成日期若后来出现切片，可单独补回望；同日新的公开经历也可单独补建，不把旧私密身份复盘再跑一遍。夜间对连续主体状态的写入带版本校验，不能覆盖处理期间已经产生的更新当下。

## 查看与召回

控制台“身份”页的“当下切片与夜间拼图”按记忆日查看，显示全部切片数量、待复盘数量、夜间回望和最近 100 片。`GET /runtime/slices?day=yyyy-MM-dd` 沿用控制台认证。

夜间回望接入 `MemoryRecallLogic` 的统一候选预算；只召回与当前查询相关的片段，并标记为主观回望。公开视图只读取本环境回望，私密视图可回望同一主体经历的各环境。回望不会把私人原文自动分享出去，也不能把回望 ID 填作认知引用。
