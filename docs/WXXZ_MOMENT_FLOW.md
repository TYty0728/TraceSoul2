## 1. 主链

```text
WXXZ 画面/音频 → 电脑识图/听写 → 服务器感知状态与候选事件
                                      ↓ JEV 精简判断
                           等待 / 补充观察 / 准入具体候选
                                                  ↓
WXXZ 明确对话 ─────────────────────────→ WXXZ Moment
                                                  ↓
QQ 入站 ──────────────────────────────→ 统一 Moment 队列
                                                  ↓
                   同一 Soul 的 Kernel → Agent → 表达与能力执行
                                                  ↓
                         本轮来源绑定的输出：WXXZ 或 QQ
                                                  ↓
                     实际表达记录 / 执行回执 → 当前状态更新
```

JEV 和感知状态属于服务器的入站准入环节；电脑 worker 只报告识别结果。JEV 选择是否提交具体候选，主模型处理已准入 Moment，不另起一套小智心智。准入不意味着必须开口，主模型可以只更新状态。

已经确认是对 Soul 的有效发言直接进入 Moment，不等 300/30 秒检查，也不受 JEV 故障影响。需要结合会话模式、明确唤醒/交互标志、转写完成状态等识别有效发言，不能把所有 ASR 文本都当作对话；背景音、电视声音、未确认转写进入候选或继续等待。确定发言寻址的具体实现随后设计，不以人脸出现自动判定。QQ 原有入站不接入新门槛。

## 2. 监控侧保存什么

| 层次 | 示例 | 去向 |
|---|---|---|
| 感知状态 | 镜头可用、可见一人、没有检测到语音、观测时间 | 有界最新状态与短缓存，不每帧保存 Moment |
| 候选事件 | 相关物体变化、人员出现、关注条件可能满足 | 带事件 ID、来源、时间、可靠性和有效期，待 JEV 判断 |
| 已准入 Moment | 值得主体处理的一次观察或明确发言 | 统一经历/对话主链，保留真实来源 |
| 运行回执 | 请求接受、播放完成、显示失败、worker 离线 | operational_events 与状态反馈，不全部混成对话 |

画面平静、没有声音通常只更新状态；定时检查可判断现有关注是否到期，不制造“又过去五分钟”的 Moment。安静本身若是关注的条件，也可形成候选。没有检测到语音不等于麦克风正常，离线、静音和过期必须区分。

未准入候选不冒充 Soul 已经历或记住的事，按缓存策略过期。JEV 只选候选 ID；服务器从实际观察构造 Moment，不让模型凭空编写事实、原话或任意 Prompt。低可靠性仍标为不确定，JEV 概率不是感知事实可靠性。

## 3. JEV 输入输出

输入复用 [精简契约](JEV_DECISION_CONTRACT.md)：当前模式和必要约束、简短关注、有效变化/现状、最近处理结果、少量具体候选。建议完整请求常态 500～2000 字符、初始上限 3000 字符，不附全量人格、记忆或原始音视频。

每轮一个 choice `next_step`：

| 选项示例 | 效果 |
|---|---|
| `wait` | 本轮不提交 Moment，保留有效关注与尚待处理候选 |
| `observe_1` | 获取一次已授权且当前可用的具体观察，暂不提交该候选 |
| `admit_1` | 将候选 event-1 转为 WXXZ Moment，排入主链 |

`admit_*` 是前一版 `engage_*` 的具体化，通过 Moment 触发统一主链，不另开主模型调用。相关变化可组成带来源列表的一个候选；一次只选择有限候选，其余仍有效的候选不直接丢弃。到期必须执行的既定任务按原流程处理，不能被 JEV 等待决定压住。

静息 300 秒、专注 30 秒检查；相关变化和回执可提前触发，近邻事件合并。关注来自主模型已有处理过程，不为每轮额外调用大模型写摘要。明确对话走独立即时入口。

准入前校验事件 ID、相关状态版本、权限与有效期。提交幂等且可恢复，不能先标成已处理再因崩溃丢失 Moment，也不能重启重复提交。JEV 网络请求不长时间占用 Soul 运行锁：读取快照，返回后重新校验并排队。没有变化的每秒新帧不推进语义版本。

JEV 失败不是 wait；保留有效待办，记录失败并退避，不自动重复付费请求。持续离线不使用旧画面假装新事实。建议同一事件最多一次补充观察，仍不足且需要主体处理时准入带不确定性的候选，避免无限观察。

## 4. Moment 的平台与内容类型分开

2026-10-18已落地统一Type和SourcePlatform：真实听写为hearing/wxxz，手动文字为message/wxxz。Role仍表示说话者，原SourcePluginId、EnvironmentJson、EvidenceType和受众边界不变；识图成功另存sight关联原消息。字段、历史迁移与界面见[统一Moment](MOMENT_SEMANTICS.md)，背景采集/JEV准入仍未启用。

背景观察准入载荷的设计示意（设备、观察引用和admission部分仍未作为采集API实现）：

```json
{
  "sourcePlatform": "wxxz",
  "type": "sight",
  "device_id": "board-01",
  "session_id": "session-a",
  "source_event_id": "event-42",
  "observed_at": "2026-10-16T10:00:00+08:00",
  "content": "桌面指示灯由红色变为绿色，多帧观察一致。",
  "observation_refs": ["obs-41", "obs-42"],
  "admission": {"decision_id": "decision-8", "candidate_id": "admit_1"}
}
```

平台、设备、会话和受众由已鉴权连接与服务器绑定，不能信任上传正文自己声明的路由。发言保留说话者和原话；观察以观察刺激进入主模型，不能伪装成用户说“灯变绿了”。明确对话记录 direct 准入来源，不伪造 JEV 调用。

已准入观察属于有意义经历，可进入 Moment；Prompt、历史与日终取材需识别内容类型，不排成 user 对话，也不能因不是人说话就全部当运行日志丢掉。准入不等于自动写长期认知或修改身份，后续仍走既有处理。设备绑定或人脸匹配不等于私密环境授权，现场受众仍按服务器规则确认。

## 5. 输出沿用本轮来源

| 来源 | 外显目标 | 目标不可用时 |
|---|---|---|
| WXXZ 设备/会话 | 同设备/会话的文字、语音、图片及已实现媒体能力 | 报告失败或在有效期内保留，不滑落 QQ |
| QQ 账号/会话 | 原 QQ 私聊或群聊的相应通道 | 报告失败，不转到 WXXZ |
| 控制台 | 保持既有调试直答和观察功能 | 不改变生活身体的输出 |

路由上下文绑定平台、设备/账号、会话及代次、受众、关联 Moment 与有效期，传给每个能力调用、TTS、后台图片任务和延迟回执。不能用最后一次活跃身体或全局可变 QQ 目标决定异步投递。断连、重连换代、受众变化后重新检查。

同一回复在 WXXZ 显示文字、播放语音共享语义输出 ID，各自记录交付结果，避免重复 assistant Moment。显示成功不冒充语音已播放，失败草稿不当作用户已听到；语音/图片完成回执仍走 operational_events。实现需覆盖多模态部分成功的表达记账。

将来用户明确要求“把这个发到 QQ”可作为独立跨平台动作设计，不作为回复自动兜底。后台事件保存自身目标，不无条件继承最近会话。摄像头拍到 QQ 屏幕仍是 WXXZ 视觉来源，不因此获得 QQ 发言权限。

## 6. Prompt 共用装配，分别提供场景说明

沿用公共顺序：同源身份 system → 合法范围历史窗口 → 稳定角色/场景说明 → 相关记忆 → 本轮状态、能力、回执及触发内容。平台差异放稳定场景说明和动态数据，不复制人格与全部装配代码。

| 部分 | QQ | WXXZ |
|---|---|---|
| 共同主体 | 同源身份、理解、记忆与连续状态的授权视图 | 同左，仍为同一 Soul |
| 稳定场景说明 | 网络聊天；私聊/群聊与发言者语义 | 身处设备所在现场；看见/听见/推断/未知的区别；屏幕和语音表达 |
| 本轮输入 | 原话、附件观察、引用关系 | 已准入观察或最终发言、时间及相关关注 |
| 能力与回执 | 本轮 QQ 目标支持的能力 | 具体设备在线与实际屏幕/音频能力 |
| 语义输出 | 正文与可选行动，经 QQ 适配 | 同一语义契约，经 WXXZ 适配 |

JEV 使用独立精简决策契约，不走完整 Agent 人格/历史装配；主模型不拆开口与思考。

当前来源优先使用本环境原始对话与观察，跨环境经历按已有可见性取用，不默认把 QQ 原始聊天放到现场当作刚刚发生。当前私密环境可能共用根 ConversationId；实现时补历史来源过滤或独立上下文键，同时保留统一主体记忆和旧 QQ 行为。路由与记忆可见性是两件事，各走明确规则。

## 7. WebUI 选择与启用流程（拟新增）

1. 在「大脑 · LLM → 供应商」新增独立的 OpenRouter Decisions 协议，明确直连/专用中转模式。当前选中转，填写基址、OpenRouter Key、中转凭据；后端保存，页面/API 不回显密钥明文。
2. 获取决策模型列表，区分模型发现和推理可用。Jev 已联调成功；GPT 上次为 403，保留模型但显示失败状态，不能只因出现在列表就标可用。
3. 「默认用途槽 → JEV（决策）」选择该供应商及 Jev 模型。原生 Decisions 不出现在聊天主模型/复盘槽；旧聊天型 JEV 配置保留并提示不适用新原生准入模式，不静默转换或回退。
4. 在「WXXZ → Moment 准入」绑定已选 JEV，提供关闭、仅记录判断、正式准入；显示频率与预算。保存模型配置不自动开启采集或付费调度。关闭/故障仅影响背景准入，明确对话仍按其已开启会话工作。
5. 提供明确标记的合成样本推理测试与状态查看：触发、候选、结果、耗时、失败、关联 Moment、输出目标。读取模型列表不暗中执行推理测试；仅记录判断不提交背景 Moment。

先完成原生客户端、配置和合成候选入口，再连接真实感知。未连接板子也能验证主链设计；实际网络入口和凭据保留在仓库外。
