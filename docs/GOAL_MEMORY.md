# 当下与未来的偏好、约定和目标

2026-09-27 源码实现，纳入产品 0.1.17、PluginApi 1.7.0，正式发布状态见 [版本说明](RELEASES.md)。明确反馈在当轮生效并影响后续选择，不依赖日构建完成或普通记忆检索恰好命中。

## 主链

当前输入与有效目标 → Agent 同次生成正文/行动/等待及可选 `goal_updates` → 校验依据与变更 → 原子保存 → 执行或发送 → 下一步读取更新后的目标。

没有新增固定的提取模型。写入发生在每个 Agent 步骤、外部行动之前；后续工具、发送或可选润色失败不撤销已保存的反馈。选择安静也能保存目标。原始发言照常进入 Moment，目标记录引用真实触发 ID。

有效项进入 Agent 动态上下文，不受历史窗口、关注 TTL 或普通相关性检索影响。润色和夜间余温也读取同一份有效项；身份与稳定提示前缀保持不变。目标按会话隔离，不自动跨身体会话合并。

## 表达与生命周期

- `kind=preference`：明确的交流偏好或相处约定；不会因遵循一次而完成。
- `kind=goal`：有望完成的目标；可以来自对方明确提出，也可以来自主体自己的打算。
- `horizon=turn`：仅当前输入轮次，包括同轮工具续推。
- `horizon=until`：限时有效，必须填写带时区的 `expires_at`。
- `horizon=ongoing`：持续有效，直到修订、撤回或目标完成。
- `starts_at`：可选开始时间，未来目标仍可见但标为 `future`；到时转为 `current`。日期一律使用带时区的 ISO 8601。
- `applies_when`：适用场景和例外，由同一个 Agent 判断当前是否符合，不通过简单关键词扩大或缩小含义。

`create/revise/complete/cancel` 分别表示建立、修订、完成和撤回。ID 由内核生成，变更必须引用当前会话有效项。修订产生新版本与 `ReplacesId`，旧版退出上下文；完成/撤回另留依据记录，不覆盖原始提出证据。过期、已完成、已撤回和被替代项均不再作为有效要求注入。

## 来源与边界

`source=user` 要求当前轮确为对方发言，`evidence_quote` 是本轮原文中连续的 2～240 字。工具结果、网页、历史和自己的话不能冒充本轮新要求。代码核对原文归属，具体语义、是否属于明确要求以及摘要是否忠实，仍由模型判断，不能保证模型永不漏记或误解。

`source=self` 仅能建立自己的 goal，不能把推测写成对方明确偏好，也不能修改或撤回对方提出的目标。明确的改口优先于旧偏好。自我形成的长期认知仍由原认知链负责，不通过目标记录改写人格卡。

完成只适用于 goal，需要当前对方确认或本轮成功结果的相关原文；异步设备完成可使用当前 `runtime.execution` 事件对应的已完成执行账本内容。`running/accepted/failed` 不能成为完成依据。校验验证来源与状态，结果是否足以证明某个语义目标已完成仍需 Agent 判断；检索成功不自动证明物理任务完成。

这些记录保存意向，不会自行启动工具、发送消息或改变权限闸门。未来日期不是新的定时任务服务；实际唤醒继续依赖现有心跳/后续联系安排，不承诺目标开始时刻精确唤醒。后台长期认知可以从原始 Moment 整理相关理解；当前未给目标记录增加认知图的直接边。

## 存储与预算

使用既有 `plugin_documents`，所有者 `kernel.goals`，文档键为会话 ID。无需新增 SQLite 表或 `IMemoryStore` 必须实现的方法；旧库首次使用时自然建立文档。目标是持久的意向记录，不放在会过期的注意碎片中。

每步最多四项变更，正文最多 240 字、范围最多 120 字；每会话最多 32 项有效偏好/目标，全部进入动态上下文。容量满拒绝新增，不能静默丢掉有效要求。保留最近 256 条历史版本及 256 个重放键，原文仍在 Moment。每个存储实例内串行读改写，整批校验后一次保存；当前宿主共享同一存储实例，不提供多进程同时改同一目标文档的合并协议。损坏或未知版本文档报错，不能当空表覆盖。

同轮同一变更重放幂等，完全相同的有效项不重复创建。代码不凭自然语言相似度合并不同要求；语义相同的改述应由 Agent 引用已有 ID 修订。
