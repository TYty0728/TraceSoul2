## 主链

当前输入与有效目标 → Agent 同次生成正文/行动/等待及可选 `goal_updates` → 校验依据与变更 → 原子保存 → 执行或发送 → 下一步读取更新后的目标。

没有新增固定的提取模型。写入发生在每个 Agent 步骤、外部行动之前；后续工具、发送或可选润色失败不撤销已保存的反馈。后台或已回应后的安静步骤也能保存目标；未回应用户时仍须回应。原始发言照常进入 Moment，目标记录引用真实触发 ID。

偏好和目标按会话保存。普通 Agent、润色与轮后相机计划读取同一本轮候选视图。夜间余温沿用下述独立只读选择。身份与历史仍按原装配顺序读取。

## 表达与生命周期

- `kind=preference`：明确的交流偏好或相处约定；不会因遵循一次而完成。
- `kind=goal`：有望完成的目标；可以来自对方明确提出，也可以来自主体自己的打算。
- `horizon=turn`：仅当前输入轮次，包括同轮工具续推。
- `horizon=until`：限时有效，必须填写带时区的 `expires_at`。
- `horizon=ongoing`：持续有效，直到修订、撤回或目标完成。
- `starts_at`：可选开始时间，未来目标仍可见但标为 `future`；到时转为 `current`。日期一律使用带时区的 ISO 8601。
- `applies_when`：适用场景和例外，由同一个 Agent 判断当前是否符合，不通过简单关键词扩大或缩小含义。

`create/revise/complete/cancel` 分别表示建立、修订、完成和撤回。ID 由内核生成，变更必须引用当前会话有效项。修订产生新版本与 `ReplacesId`，旧版退出上下文；完成/撤回另留依据记录，不覆盖原始提出证据。过期、已完成、已撤回和被替代项均不再作为有效要求注入。

## 来源与边界

`source=user` 要求当前轮确为对方发言，`evidence_quote` 是本轮原文中连续的 2～240 字。工具结果、网页、历史和自己的话不能冒充本轮新要求。代码核对原文归属，具体语义、是否属于明确要求以及摘要是否忠实，仍由模型判断，不能保证模型永不漏记或误解。

`source=self` 仅能建立自己的 goal，不能把推测写成对方明确偏好，也不能修改或撤回对方提出的目标。明确的改口优先于旧偏好。自我形成的长期认知仍由原认知链负责，不通过目标记录改写人格卡。

完成只适用于 goal，需要当前对方确认或本轮成功结果的相关原文；异步设备完成可使用当前 `runtime.execution` 事件对应的已完成执行账本内容。`running/accepted/failed` 不能成为完成依据。校验验证来源与状态，结果是否足以证明某个语义目标已完成仍需 Agent 判断；检索成功不自动证明物理任务完成。

这些记录保存意向，不会自行启动工具、发送消息或改变权限闸门。未来日期不是新的定时任务服务；实际唤醒继续依赖现有心跳/后续联系安排，不承诺目标开始时刻精确唤醒。后台长期认知可以从原始 Moment 整理相关理解；当前未给目标记录增加认知图的直接边。

## 存储与预算

使用既有 `plugin_documents`，所有者 `kernel.goals`，文档键为会话 ID。无需新增 SQLite 表或 `IMemoryStore` 必须实现的方法；旧库首次使用时自然建立文档。目标是持久的意向记录，不放在会过期的注意碎片中。

每步最多四项变更，正文最多 240 字、范围最多 120 字。每会话最多 32 项有效偏好和目标。容量满会明确拒绝新增。保留最近 256 条历史版本及 256 个重放键，原文仍在 Moment。每个存储实例内串行读改写，整批校验后一次保存。当前宿主共享同一存储实例，损坏或未知版本文档报错并保留原件。

同轮同一变更重放幂等，完全相同的有效项不重复创建。代码不凭自然语言相似度合并不同要求；语义相同的改述应由 Agent 引用已有 ID 修订。

## 2026-11-23：普通对话读取条件复核

首要目标是让阿循把注意力放在眼前这轮该关心的事上，保留偏好和约定带来的生活细节。用户明确，约定的时间窗口也是适用条件。普通首轮仍以 8,000 输入 token 为预算目标。0.1.99 样本的普通 Agent 直接读取全部活跃项，体积见 [Prompt 装配核对](PROMPT_ASSEMBLY.md#2026-11-23-普通-agent-请求体积核对)。

候选读取条件包括长期相处边界、按提出时刻确定的时间窗口、当前话题和近轮承接、生活条件变化，以及对方主动追问、修订或确认完成。时间窗口、截止点及约定时刻用于不同的判断。时间已过且没有结果证据的记录可退出日常注入，查询时保留其过期和结果未知的状态。判断当前场景时也读取实际已知条件，未知条件保持待确认。

同一场景命中多条时，优先呈现当前仍适用的偏好、与它直接相连的开放目标，以及能影响选择的具体原因或例外。保留可按需查阅的原件与修订历史。显式追问可读到适用受众范围内的旧记录，同轮行动续推保留已使用的记录引用。

验收先检查同一批对话中对当下意图的承接、相关约定的及时浮现、具体细节的保留，以及无关旧事是否抢占回复重心，再对照输入用量。以下设计的落实范围见本地第一版。

### 普通对话的激活与注入方案

普通回复沿用主 Agent 的一次生成。程序在组装动态段前准备偏好和目标的短视图，主 Agent 同次判断适用性并表达或行动。常驻边界沿用户明确确认的范围保留。当前正在推进的约定、同轮已使用的目标引用，以及和此刻安排有关的结构化时间窗口，由程序优先带入。有新修改时使用最新版本，按原会话和受众范围核对。约定的相对日期按提出该日期的发言时刻解析，历史条目日期有歧义时保留待确认状态。

场景候选复用 Host 已有的本地 BGE 向量服务。先按受众、生命周期和版本限定可读条目，再分别以本轮输入和紧邻的对话、当前仍在推进的关注取候选。当前明确话题优先，省略指代时用近期对话承接。记录向量可在载入和更新时后台准备并按版本缓存，同轮续推复用。向量分数只用于找到可能相关的条目，允许空结果。向量不可用或记录向量尚未就绪时，保留确定性命中和明确词面线索。首轮选择保留短正文、能影响决定的条件和具体细节，分别呈现当前适用项和可能相关线索。

模型在原回复请求中结合用户当前说法判断候选里的条件、否定、改口和计划状态。证据原话、更多同类项以及已过期或替代的历史，只有在追问、核对或确有必要时才经现有 Agent 读取流程展开。现有 `memory.recall` 面向经历、认知及原文，目标目录需要接入该读取流程或提供对应的读取能力。超出首轮材料的读取可能需要主 Agent 续推，普通回复不固定增加模型请求。短引用由程序映射到原条目，变更沿用现有 ID、来源与受众校验。

先用相同记录和固定时间离线核对哪些条目入选，覆盖无关闲聊、半句承接、时间提醒、同关键词但不同意图、条件尚未成立、改口和查历史。再用同一主模型对照完整注入与候选注入的实际回复，先看是否接住对话及保留必要细节，再记录输入 token、首字延迟和读取引起的续推次数。

### 偏好和目标的主题索引

偏好和目标增多后，按现有 LifeTag 的范围读取方式缩小候选。记录可引用已存在的主题 ID，继续以原条目为正文、条件、来源及版本的权威记录。主题名称和定义用于导航，并可沿用已有的正反例与向量路由。同一条记录可以引用多个确实适用的主题。换一种说法或修订同一意向时优先复用已有主题与记录关系。适用情境、时间或例外不同的记录可以共存。旧条目沿相同索引补标，未知主题仍可按已有引用、时间及显式读取查到。

查询先限定主体、会话受众与记录状态。当前话题和紧邻对话匹配少量主题，在主题范围内读取短候选。已明确的相处边界、当前正在推进的事项和当下值得处理的时间窗口各自可命中，合并后按条目 ID 去重，再按本次任务的输入预算取用。题意不明时允许少量或空候选，显式追问承接相应范围的读取。过期、完成与被替代的版本可在查历史时读取。

轮后整理同样读取变化所涉及的这部分候选，由子代理结合证据整理当前关注。见 [主 Agent 按需请求轮后整理](AGENT_SENSES_PLATFORMS.md#2026-11-23主-agent-按需请求轮后整理的设计)。当前每会话 32 项是存储上限，存量规格调整须待主题读取和预算生效后单独验证。候选方案需要验证候选体积与存量解耦、时间查询能跨主题命中、同主题不同条件能保留，以及子代理在记录增多后仍能接住真实转折。

### 分步实施与体验调整

1. **先切换轮后整理的触发方式。** 主 Agent 在原有回复输出中可以带简短的整理意图，有实质变化时由它自行判断是否请求。完成本轮后沿用现有整理队列、快照、关注与共同场景输出，以及版本校验。首版提示给自然例子和判断余地。整理未返回时下一轮沿已提交状态继续，明确改口仍由主 Agent 在本轮处理。单独验证新旧轮次交错、慢响应、失败以及迟到结果。
2. **再接偏好和目标的渐进读取。** 先复用已有 LifeTag、时间窗及正在推进的条目引用，候选条件设得宽一些，保留相邻主题、短句承接和适用条件。默认读已有关注和少量候选，话题深入后按范围展开详情，显式追问沿可见原件继续查。标签未知的旧记录仍可按引用、时间或显式查找使用。先在偏好和目标这一段对照原注入，观察接话质量和首字延迟。身份、榜单和日复盘不作为这一轮改造的依赖。总量预算和受众、版本、原始时间依据沿用；存储上限单独处理。
3. **根据体验收紧具体环节。** 用少量标注案例对照漏接、误带旧事、重复提醒和整理过密，记录候选规模、主模型首字延迟和后台请求量。漏接时先看话题承接、时间窗和标签归属；跑题时调整对应主题或时间条件；请求太密时再合并同一事项的重复整理。一次只调整对应问题，复跑原例与相关的正常对话。以自然承接、具体生活细节和能放下旧关注为先，8,000 输入 token 为普通首轮预算目标。

### 2026-11-23 本地第一版
