# GLM JSON请求与组件兼容

## 0.1.73行为

GLM结构化请求显式传递`response_format: {"type":"json_object"}`，主用、备用及格式纠正沿用同一组装路径。普通文本请求和既有协议兼容重试按需省略该字段；思考开关、强度、备用顺序和调用上限保持。

复用PluginApi已有的DeepSeekChatRequestData，不向共享GLM DTO新增字段。调试中曾出现新Host引用新增字段、旧PluginApi未同步的组合，触发MissingFieldException；请求组装方法编译时解析该引用，因此其他兼容模型也会在HTTP发送前失败。正式版本保持PluginApi 1.16.0，可使用旧共享契约。

失败提示区分“模型返回空白正文”和“程序组件版本不一致或缺失”。组件装载错误不切备用，避免把本地部署错误伪装成供应商故障；包装异常仍能归类，提示不泄露原始请求或供应商诊断。

JSON模式不保证业务字段正确。例如goal_updates创建操作必须省略id，修订等操作必须引用有效目标；现有严格校验与有界纠正继续保留。HTTP200也不代表正文有效，不改动已有空白响应切换策略。

## 验证与运行边界

模拟HTTP覆盖GLM主用/备用与思考开/关、首次非JSON后纠正、恢复后无持久错误、普通文本和协议兼容字段省略。现场实际Host/旧PluginApi离线组合在三种模型各自JSON/文本共六种请求全部复现缺字段；修正Host与同一旧PluginApi六种全部通过，无网络调用。

发布构建与检查结果见[版本记录](RELEASES.md)。更新包需要由用户在网页执行更新，发布本身不更新服务器、不解除日构建保护、不重跑任务；真实模型输出质量仍需更新后观察。
