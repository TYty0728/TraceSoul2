# 统一 Moment 与 WebUI 分区

2026-10-18，按用户要求将经历的感知类型与来源平台分开持久保存。此修订替代早期把WXXZ当作内容类型、把听觉标签直接拼入正文的做法；主体、人格、记忆权限、准入与输出路由仍沿原主链。

## 数据与类型

`MomentRecord` 新增有索引的 `Type`、`SourcePlatform`，以及关联观察的 `ParentMomentId`；`PluginEventData` 同步提供这些字段。Role仍表示发言/表达者，EvidenceType仍表示证据性质，SourcePluginId仍是实际插件。设备、账号、会话、受众和记忆可见性继续由Environment控制，类型与平台标签不提供权限或输出地址。

| Type | 展示标签 | 含义 |
|---|---|---|
| `message` | 我收到消息 | 收到的明确文字/平台消息 |
| `sight` | 我看见 | 已实际取得的视觉识别观察 |
| `hearing` | 我听见 | 实际采音得到的听写/听觉输入 |
| `feeling` | 我感受到 | 身体/环境感知接口，不自动把内心情绪变成外部事实 |
| `touch` | 我碰到 | 接触/触觉观察接口 |
| `expression` | 我表达 | 实际输出的语义文字，保留原表达者角色 |
| `event` | 发生事件 | 其它语义经历/旧记录的保守归类；运行回执仍排除 |

平台规范名包含 `qq`、`wxxz`、`console`、`robot`、`system`；空来源为unknown，未知插件保留来源ID。builtin.onebot规范为qq，builtin.dialogue规范为console；内部事件来源为system，不把目标QQ当作外部输入来源。新适配器提供类型，并登记平台族映射；设备/会话继续独立绑定。

新正文保存实际内容，不再塞入听觉或QQ来源前缀；页面和Prompt从字段生成标签。板载听写仍核验一次性captureId、原文与会话，手写「我听见」不能冒充采音。界面的类型选择器只用于筛选，不用于伪造感官输入。

```json
{"type":"hearing","sourcePlatform":"wxxz","content":"你好，我们继续。","sourcePluginId":"wxxz"}
```

## 消息与观察

QQ/控制台消息带图时，原消息仍是message，识图成功后另存sight，用ParentMomentId关联原消息。视觉观察使用Role=perception和plugin_observed证据，不伪装成用户说的话；一次输入仍只跑一次主体处理，并沿原来源输出。

识图失败/未配置时只提供失败状态，不造「我看见」事实。当前观察进入本轮动态上下文；后续历史保留观察与平台标签，公开/私密作用域不变。复盘取材保留类型、平台与关联ID，观察主体键为perception:<平台>，不当作用户自述。

feeling/touch与机器人平台已具备入库、筛选契约，但本轮未接摄像头、温度或触觉设备，不自动录音或产生机器人事件。既有明确语音直接进入主链；背景采集/JEV准入未在本轮开启，见[WXXZ主链](WXXZ_MOMENT_FLOW.md)。

## WebUI

| 分区 | 内容 |
|---|---|
| 日常 → 经历与对话 | 统一经历、独立类型/平台筛选、文字发送、小智通话；处理详情折叠 |
| 日常 → 实时状态 / 一起玩 | 当前状态与游戏交互 |
| 内在 → 身份 / 记忆 | 身份、认知、记忆与复盘 |
| 连接与能力 → 身体与感官 | 设备连接、小智听写、声纹录入与诊断、播放方式、QQ连接和身体情境 |
| 连接与能力 → 大脑 · LLM | 模型槽、供应商、千问音色/试听；上下文与心跳单独成块 |
| 连接与能力 → 能力与插件 | 能力启停、插件安装与专属配置 |
| 维护 → 日志 / 系统更新 | 运维与版本更新 |

管理后台统一浏览当前角色各来源经历，不能因此把公开/私密历史合并给模型。每行展示实际发言者、类型、平台与时间，公开场景不把其他人显示成本人。发送来源单独选择，筛选不改变发送平台；标签和原文均转义展示。

`GET /moments/catalog` 返回筛选项；`GET /moments?source=all&type=hearing&platform=wxxz` 查询统一经历。原按会话查询保持兼容，Prompt仍按原Environment作用域取材。
