# 固定唤醒应答缓存

名字唤醒的“诶，我在。”可通过本地千问或远端角色语音预先生成最终WAV。名字监听启动前自动准备；已保存的名字设置旁也有“预生成唤醒语音（不播放）”，不需要开发板连接。先保存应答文字和播放音色再点按钮，开始监听/通话时禁止额外手动预生成。

这只优化固定应答取音。识别名字、声纹准入、30秒注意力、Moment、主体回复和输出平台规则不变；普通聊天回复、网页文字试读、音色抽卡仍走正常合成，不自动缓存。系统测试音色不支持预生成。

## 远端角色语音（2026-10-24）

远端由当前Soul的Host在内存保留一份最多4MB的唤醒WAV，最长30字。首次显式预生成或启动名字监听会调用已配置的远端语音接口，成功后返回miss；相同配置再次取音返回hit，不再调用供应商。不会向远端发送本地千问专用缓存头。Host重启会失去这份内存缓存，下一次需要重新生成。

每次使用都读取并校验当前远端配置，缓存键包含实际URL、凭据、模型、音色、代理及应答文字；保存播放设置也会作废旧缓存。缓存键与凭据不进入公开状态。相同应答的并发请求串行复用，错误和无效WAV不缓存，不重试、不切换声音。远端音色供应商在相同音色ID内更新内容无法自动察觉，可重新保存播放设置使缓存失效。本地千问继续使用下文服务端持久缓存。

当前远端0.1.71已加载本次未发布的Host/UI补丁，原程序/页面有私密备份。真实鉴权预生成：首次2518ms、324748字节，第二次hit、取音0ms（毫秒计时精度）、相同字节数；该验证没有连接会话、录音、播放或主模型请求。服务器实际返回页面已包含远端支持文案与新调试按钮。Host Release构建、WXXZ专项及六项WXXZ页面脚本通过；专项覆盖缓存命中、配置变化、并发、普通聊天不复用及失败不缓存。实板唤醒命中后的播放仍待用户测试。

## 本地千问请求和失效

Host使用已配置的本地千问供应商地址/Key，请求原`POST /v1/audio/speech`，只为固定应答增加`X-TraceSoul-Wake-Cache: v1`。正文仍是兼容语音接口的model/input/voice/response_format。服务返回`X-TraceSoul-Wake-Cache: miss`（已生成并写缓存）或`hit`（读取最终音频，合成耗时0）。旧服务不返回该头时允许正常WAV交付，但状态显示“服务未确认支持缓存”，不宣称预生成完成。

缓存键覆盖应答文本、合成参数、模型文件版本标识、实际选中的参考音路径/内容摘要和参考文本摘要。`character`在抽卡工作台改选、参考音或应答文字改变后，下一次请求会生成对应新缓存。每次取用重新核对，界面显示的“上次预生成/上次唤醒取音”只是历史回执。失败不重试、不改用别的声音，也不把旧音频冒充新配置。

缓存只允许最多30字、有效PCM16 WAV（单/双声道，8～96kHz，最长30秒，最多4MB）。在本地语音运行目录的`cache/wake-audio/`原子保存受限权限文件，最多16份；文件只含版本/散列/Base64音频，不存Key、明文请求或参考音路径。损坏条目不播放，按未命中重新生成一次；命中可在GPU忙时读取，未命中且GPU忙则拒绝，不排队重试。服务重启后可复用匹配版本的磁盘缓存，仍需模型ready。

缓存API每次仍必须带Bearer Key，浏览器工作台会话不能替代`/v1`的Key；没有新增公共音频下载地址。面板`POST /wxxz/wake/audio/prepare`沿用Host鉴权，只返回取音回执，不回传音频、不采音、不播放、不写Moment、不调用主模型。自动准备在Soul运行锁外等待GPU；启动中暂停会取消启动等待，不在预生成结束后偷偷开始采音。已经进入GPU的合成可能完成并留下对应缓存。
