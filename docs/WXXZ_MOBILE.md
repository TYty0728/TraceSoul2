# 开发板通过手机热点外出演示

## 链路

固件0.4.9增加主动出站连接。板子和家里电脑各自连接独立的TCP中继，无需同一个局域网，也无需手机端口映射。电脑继续运行5089桥、ASR、VAD及声纹模型；原SSH回环隧道让服务器Host访问电脑桥。Soul仍只有原服务器实例。

手机热点 → 板子出站连接 → 服务器字节中继 ← 电脑桥；原Host通过SSH回环隧道调用电脑桥。电脑必须保持开机、联网、不休眠。仅手机和板子在外，不代表已经完全脱离电脑。

## 协议与恢复

- 中继使用独立32字节随机接入密钥，注册时验证带角色和随机挑战的HMAC-SHA256；不传明文密钥。中继不持有板子设备私钥或控制令牌。
- 配对完成后直接透传原TLS协议：电脑验证原板端证书，再在TLS内提供原设备控制令牌。传输内容始终在电脑与开发板间加密；中继注册本身不是控制授权。
- 每条命令/采音流独占一次配对；结束后板子重新连接。失联或未知结果不重播、不自动切USB。中继限制连接数、缓冲和闲置时间，关闭前排空已收尾的回执。
- USB专用`relay_setup`写独立NVS项，不读取或重写热点密码；原`wifi_setup`仍管理局域网配置。完整Flash备份含敏感配网及密钥，必须保存在仓库外受限目录。
- 本机配对文件新增`relay_host/relay_port/relay_key`，`mode=relay`才使用移动链路。控制页「切换到移动网络中继」先验证真实TLS鉴权，成功后才保存模式；失败保留原模式。切回局域网应先切USB读取当前地址。
- 回退可以切USB或使用备份恢复旧固件；旧固件忽略新增relay NVS项。不要擦除NVS。

## 安装与演示

1. 先按维护约定检查服务器忙闲与迁移进程、取得维护租约，再安装独立`mobile_relay.py`服务。仅开放服务所需TCP端口，使用受限配置文件；原Host不需要更新或重启。
2. 完整备份板端Flash并核对摘要，构建/刷写0.4.9。保持USB；停止电脑桥后运行`Provision-Mobile.ps1`，参数指向仓库外私密配对文件和中继配置文件。密钥不通过命令行或聊天传递。
3. 启动电脑桥，检查USB hello的`relay_stage`；控制页切「移动网络中继」，确认真实hello而非只看热点连接状态。随后恢复原SSH回环隧道。
4. 在手机打开原Host控制页，选择适合公开演示的会话范围。公开场合不要使用本人私密会话。只有明确开始通话才采音；关闭网页不等于结束通话。
5. 验收应包括手机使用蜂窝网络、电脑留在另一网络、开发板充电宝冷启动、屏幕/语音输出、真实人声与完整回复、结束及断网恢复。未完成这些步骤不能宣称外出演示已通过。
