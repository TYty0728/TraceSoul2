# 主模型二级、三级备用

2026-10-23：纳入0.1.61；发布验收见[版本记录](RELEASES.md)，未部署服务器。备用顺序由用户在网页选择；旧配置默认不启用，不替用户选择真实 API。

## 配置

在「大脑 · LLM」先保存主模型，再在「主模型备用顺序」选择二级、三级供应商及模型，点击「保存备用顺序」。留空关闭对应级。建议选择不同供应商，降低同一接口故障对全部候选的影响。

配置保存不请求模型，不开始采集或发送消息。新轮次读取配置快照；正在进行的轮次不受中途编辑影响。选择必须是已配置密钥且启用的聊天模型，不能使用原生 Decisions 或 TTS。相同接口和模型不能重复；删除供应商或模型清除对应引用，之后停用的模型会跳过并记安全日志。

`GET/PUT /providers/main-fallbacks` 返回或保存 `{ secondary: { providerId, model }, tertiary: { providerId, model } }`，使用现有控制台鉴权与来源校验。两项一起校验、一起保存；无效选择不会部分覆盖。配置存于角色原有 `llm-providers.json` 的 `mainFallbacks`，接口不返回密钥。

## 请求与状态

- 范围是主模型承担的对话、主动联系及夜间余温；复盘、JEV、识图、语音、生图及显式供应商调用继续使用原路由。
- 配置备用后，单次模型请求在每个候选只发送一次 HTTP 请求，最多三个候选；停用原通道的网络、空响应、温度兼容等内部重试。每个候选沿用各自的超时设置。
- 超时、网络连接失败、HTTP 401/402/403/404/408/425/429/5xx、供应商异常响应或空内容可切换。用户取消立即结束；业务输出约束仍由原有结构纠错处理，未知业务异常不会被当作接口故障重放。
- 切换携带本轮原消息和缓存键；不重新执行 Kernel、工具、发送或入库。成功的备用承担本轮后续推理与表达，失败通道在本轮不再尝试；下一轮从用户保存的主模型开始，不改写该选择。
- 一个 Soul 仍使用原有身份、记忆、runtime 和本轮输出目标。供应商切换只影响推理请求，不创建角色分支、不更换 QQ/WXXZ 收件目标。
- 中间通道失败且备用成功只写切换日志，不生成整轮失败报告。全部可用候选失败才报告；错误记录不暂停新对话，也不会自动重放已经失败的轮次。完成日志和用量反映实际成功供应商及模型。
- 两个备用都未配置时保留原供应商重试行为。模型的一次结构纠错、工具后的续推属于新的推理步骤，不能把单次请求的三个候选上限解释成整轮所有推理总共只有三个 HTTP 请求。
