## 白天与深夜的分工

白天沿用单次 Agent 判断与按需能力调用。完成轮次时追加本轮已有的 inner、mood、attention、today、活动与来源，不再另叫模型整理，不创建长期认知或自动改写身份。最新主体状态用于下一轮接续，历史切片另存，避免当天轨迹被滚动覆盖后失去中间变化。

深夜沿用北京时间 04:00 记忆日和日构建调度：

1. 按时间、来源环境处理所有待复盘切片，保留经历、感受变化、矛盾与未解之处。每批最多 80 片 / 16000 字，前两批已落地回望用于衔接。
2. 形成持久的当天拼图片段，原切片及其触发来源一并保留。不强行给四领域填条目，也不将感受自动认定为事实或性格。
3. 私密事件整理继续原流程；私密和公开认知各自在自身环境内使用完整原文与对应切片。每批最多 200 条 / 24000 字（原文与切片一起计入），分批覆盖全天，取代“只看最后 200 条却标整日完成”。单条超过预算则报错保留，不截断冒充完整依据。
4. 私密身份摘要仅引用有效且用途匹配的认知。来源被修订、削弱或退役时，旧摘要退出当前视图；新认知可直接参与自我呈现，之后再压缩成摘要。
5. 当天回望与认知均可在以后相关场景被召回。主观回望明确标注其性质，不可作为 `attention_links` 中的认知 ID 或新的外部证明。

切片批次的“落地回望 + 标记已处理”在一个事务中提交。失败保留待处理项，重跑不重复已成功批次；迟到切片与只有后台感受的日期也进入补偿队列。整日失败仍沿用停止自动重试的保护。旧日已完成时可补切片回望与公开经历，不重跑已完成的私密身份管线。详见 [当下切片与夜间拼图](RUNTIME_SLICES.md)。

## 人格连续与私密边界

各环境从同一身份来源生成视图。原 `PublicIdentity` 配置现在是共同自我描述，同时用于私密与公开；保留旧字段便于升级。人工卡默认固定，不能被复盘覆盖；无来源的旧卡保守保留，不自动给它们编造认知引用。

分享批准绑定卡片或认知的当前内容与版本。正文、依据或版本改变后旧批准不继续生效；批准摘要不代表批准私人证据。对专属用户的理解始终带对象，不套在陌生人身上。公开经历按其环境进入同一拼图，在私密视图可用，在其他公开环境需明确批准后使用。

主体总体情绪使用有限值，细致原因分别带来源。公开交流的新感受会影响同一主体，局部场景/关系和固定发送目标仍各自保存。实时轮次与日复盘按版本提交，较旧的复盘不能覆盖更新的当下。
