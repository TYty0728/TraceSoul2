# 每日复盘：四步流水线

2026-10-30 按用户确认重写；2026-11-11进一步按“十万字以内全文一次、每个后续环节一次、移除无依据配额”简化。本文取代旧文档中“观察、细节扩写、全天回望、全量认知、逐卡演化、榜单晋升”作为每日完成条件的设计。以下现行语义为本地实现，尚未发布部署；历史版本的限额与JEV说明保留用于旧检查点恢复。

## 执行语义

入口为 `Tools/Migration/DailyReviewPipeline.cs` 的 `DayBuilder.RunAsync`。记忆日仍为北京时间 04:00 至次日 04:00。

1. **完整互动提取事件**：当天未处理的私密原文（双方问答、助手主动/连续表达、工具观察）按时间合并，正文合计不超过100000字符时一次读取，不按48条、16000字或会话再切小批。不同会话保留请求内短编号，角色/时间/证据性质/全文均保留。超过100000才按完整消息分批；单条超过100000明确失败，不截断或假报完成。恢复只读尚未提取的来源。
2. **挑选事件**：全部候选一次判断，按实际价值选择，也可一件不选。不设事件或入选条数配额，不再先分组选择再全局选择；程序写入事件榜，无额外排序调用。
3. **形成当日认知**：按用户最新要求，不检索或注入旧认知，也不提供existing字段。一次根据入选原件形成当日理解，只允许create，不猜测历史目标去印证或修订；同批重复含义合并、复述旧事不当作新的事实。新日期使用`batch-v1`，不逐项调用JEV。条数、来源数、主题数和正文无额外配额；真实来源、同会话与受众、主题关联检查及全批事务保留。旧记忆不删除；这一步也不再负责跨日语义去重或历史修订。普通聊天仍使用自己的写入契约。
4. **更新当前 runtime**：程序只列出非固定、同类别有本轮依据的卡片，每项明确purpose及allowed_cognition_refs；认知表也只提供这些卡片可用的依据，当前状态从当日事件取材。不带旧卡正文、旧认知或上次runtime。无可更新卡片时cards=[]仍可更新状态；未输出的槽位和空状态字段保持原状。正文替换读视图，不逐日追加；引用只能选对应清单。存储层仍校验卡片/认知版本和实时主体版本，防止覆盖并发新状态。

2026-11-12重设计：第三步明确“事件记发生，认知记今后如何理解和选择”，不要求事件逐条转认知；同一问题合并并采用最终明确版本，临时日程和操作步骤留在事件。统一说明self/other/relation/expression_habit的对象，personality是助手固定设定、不是用户性格。公开提炼使用同一语义说明。第四步纠错给出cards[i]、实际slot/引用、允许编号和省略办法，并带失败草稿，仍只一次整份纠正。回归与未验收范围见[第三四步契约重设计](REVIEW_SIMPLIFICATION_AUDIT.md#2026-11-12第三四步契约重设计)。

私密四步所有短编号均是请求内的 `1、2、3…`，不要求模型生成或抄写数据库 ID。新路径每环节正常一次，四步均需执行时共4次普通模型请求、0次额外JEV决策。结构或引用错误至多一次整份纠正；第4步不再逐字段追加压缩调用。每日入口使用单次HTTP客户端，不再套5/10分钟网络重试。空日不请求模型；没有事件/入选事件时跳过不必要环节。卡片和runtime提示保持简洁当前状态，取消人为字数拒绝和存储截断；固定卡/同slot引用约束保留。

向量编码由本地 BGE 完成，按内容哈希复用；事件向量化和主题分类目录检索保留，旧认知召回已从新日复盘生成入口移除。公开经历同样只根据当日原件create，不注入历史认识；按受众隔离，每环境正文十万字符内一次判断并整批提交，不再200条/24000字符/16条分批或额外比较整理，也不进入私密卡片/runtime请求。历史检查点沿用其执行器，不重放已提交内容。

最新上下文流向、真实材料离线对照及剩余输入见[停止历史回灌](REVIEW_SIMPLIFICATION_AUDIT.md#停止历史回灌同日追加)；下文保留前一次清理及试跑时的事实，不代表仍带入旧认知。

## 2026-11-11：白天事件短句能否替代全文（只读核对）

以下为实施前的诊断记录；“未修改”指当时状态。当前实现和用户最终确认范围以上述四步合批一节为准，不再采用目录提名/补提取的多阶段建议。

### 用户确认的输入单位与覆盖缺口

用户要求10万字以内优先一次复盘，不以固定小批次或逐项决策制造大量请求；输入须覆盖完整双向互动，包括阿循主动、连续消息，不能只用用户单边原话。此前讨论的“轨迹＋用户消息”不是获准的替代方案，未写入流水线。实现分批时须按整体请求及模型实际预算核对，不能把字符阈值误作所有模型的token容量保证。

11月10日数据进一步核对：73条用户message共3260字符；176条expression共35629字符，其中96条QQ媒体/表情标记、80条其他表达；3条外部event资料16953字符。70条轨迹绑定问答触发消息，73轮有实际正文的问答中3轮未写today。另15次scheduler_trigger中6次生成非空reply，6条均与当天expression正文逐字匹配，但15次均无today/轨迹记录。因此主动发言真实存在而白天目录未覆盖，不能据短目录直接标记整日完整复盘。只读核对未删减任何原件。

人工阅读66条概览及轨迹，并回查18条关键事件来源：大体保留当日主线，但存在适用条件省略、回复压成泛化动作、文字场景与实际行动未充分区分的问题。需要保留双方表达的含义、理由、承诺、纠正、结果及来源，主动消息按实际时间串联而非强行配一条user。可复用短事件，但先补其互动覆盖；缺项应补对应双方原件，不默认额外开一轮筛选请求。

另：夜间入选的前两项事件共用11月10日04:04:45的500字符expression，与11月9日night.residue发送记录相差779毫秒；是前一日梦话的发送存档。表达本身属于当日发生的行为，但回顾的旧事不能因此变成新的独立事实或重复印证。复盘重构需保留这层来源区分。

### 同日调用放大核对

11月10日任务在11日04:00及07:23～07:34的留痕，普通模型26次：事件提取15、事件选择3、认知草稿6、runtime更新2。其中DeepSeek4、GLM系列6、Kimi16；JEV检查点另保存21份有效请求答案，不含失败/未缓存决策的可能额外请求，因此合计至少47次。Kimi接手续做阶段为16＋21＝至少37次，不含随后梦话或白天轮后整理。

认知分成16/5条来源两批。5项create各有一次LLM草稿，再分别做target、source支持关系、topic适用关系、route归属4次JEV请求；另1项空草稿经JEV确认结束，共6＋21＝27次。source问项已在同次请求批量发送，不能误报为每条原句一次请求；topic问项也分组发送。本次没有额外主题优先选择调用。有效答案缓存能避免恢复重放，但不会减少正常首次执行的这条串行链。

优化重点应是减少重复携带材料与可合并的决策请求；单纯减小原文或再加选择阶段不保证减少总调用。可评估同批一次生成多项草稿、把无依赖的JEV问题合并、只为依赖分支追加调用，仍由程序绑定合法候选并验证来源。一次发送整天并输出全部操作会牵涉输出容量与恢复粒度，不宜仅按输入字符数决定。此次只统计与分析，未修改复盘调用编排。前述夜间新选择阶段仍仅为本地代码，确会增加一次普通请求，不应将它宣称为总调用/总token优化。

白天`Agent.today`写入`day_trajectory_entries`，概览整理器按来源生成15～25字、程序最多60字的事件句，并保留轨迹来源映射；未被概览覆盖的轨迹在阅读时补入。`new_fact`便签及runtime切片是不同材料，不等同于已核实的事件/认知。轨迹绑定触发Moment或OperationalEvent，现有概览的sources是轨迹ID，不能直接当作全部用户发言、回复和执行回执的完整证据集合。

11月10日实际四步SourceIds共252条（73 message、176 expression、3 event），原正文共55842字符；白天轨迹70条、2317字符；缓存概览66句、1738字符、覆盖69条轨迹（阅读器会补剩余轨迹）。这些数字不代表短句完整表达了原文全部语义，也不能按70/252推导“丢了182条”，两者粒度不同。入选8事件对应21条来源。

当前第1步仍从当天原文分段重提事件；第2步只读摘要；第3步仅回读入选事件原文并形成认知/JEV决定；第4步读入选摘要和认知，不重复全天全文。故有空间复用白天目录减少第1步重复加工，但不能简单把全部原文替换成摘要。

建议后续路径为白天事件目录提名→选中事项按真实来源回读核对→缺记录、来源不全、相互矛盾或未覆盖的轮次补提取→形成认知/状态。需先补齐轮次输入、实际表达及行动回执的可验证来源覆盖，并对未入选/无便签原文保留查证与遗漏检查，不能把未读取材料标作已核实。本轮仅评估，未修改四步复盘、检查点或真实数据。

## 第3步原生JEV接入（0.1.90）

`JevCognitionReview.cs`按会话切段，再按每项认知最多16条证据的现有硬限制分批，每批最多3个串行工作项。LLM每次只生成summary、scope、exceptions三个正文字符串，不生成操作、目标、来源、类别或领域。正文格式最多纠正一次；草稿先保存，传输失败可续接，不重新生成已保存草稿。

原生JEV只回答程序提供的choice：新增/已有目标/跳过/待核对，已有目标再判断印证/修订/跳过/待核对。首版不开放weaken/retire。逐句判断支持关系，仅从支持来源对应事件的主题中选主题；支持关系不明确则待核对。0.1.90在相关主题超过4个时直接阻断，0.1.91改为下述有数量约束的选择。新认识选择程序定义的类别/领域组合；印证和修订直接继承目标类别及领域，印证还复用目标正文。程序绑定实际ID并执行现有校验，JEV不直接构造数据库写入。

空草稿需要JEV确认无剩余变化，不能仅凭LLM空字符串标记完成。已处理工作项包含草稿、状态、操作和绑定来源，供后续判断去重。每批仍按最多3项的认知选择预算完成，不意味着穷尽原句中所有可推导认识。调用数量比旧操作包增多；每次实际JEV请求与LLM共用256次派发上限，原生JEV无自动重试。服务失败立即退出，语义待核对可继续独立批次，但整日保持未完成并进入失败保护，需检查后手动续做。

检查点记录草稿、有效答案缓存和单项状态；正式认知与committed进度同事务。来源/身份变化时拒绝提交，候选认知或主题变化时拒绝旧决策，下次重建未完成项。待核对答案不缓存。正在续做的JEV日期冻结来源快照，迟到原句下一轮处理。已完成项不重放，未完成项的合法答案只在相同输入与版本下复用。

Migration实际回归覆盖Version7/8：乱序及不连续编号、只引用列表第二件事件、重复/缺失/未知编号、记录时间无损转换、已知回顾与普通表达区分、连续助手消息完整保留，以及原有空结果/跨会话/事务故障恢复。此检查验证协议与存储关联，不证明模型所选依据在语义上成立。实测及局限见[明确编号测试](REVIEW_SIMPLIFICATION_AUDIT.md#可读时间与明确编号真实测试)。仅本地与隔离测试，不部署。

### 同日追加：以内容质量验收提示修订

用户明确以数据质量而非字数/条数作为目标。沿原件与四卡起点逐层检查事件、认知、回顾和当前状态；主观感受可以鲜明，事实归属、时间、判断依据与确定程度应清楚。尤其区分已有认识得到再次体验与本日新增、修正或深化的理解，不能以措辞新颖代替认识增量。

### 同日追加：区分再次体验与认识增量

按用户要求继续一轮，只替换Version8第一轮的认知说明，其余提示和输入协议保持。四卡中已经成立的认识作为起点，当天再次体验或得到印证的认识连同具体感受留在events；出现新的联系、缘由、适用条件或判断修正时，认知正文直接落在新增部分，并由所引经历说明成立依据。四卡仅为当前认识概览，未覆盖之处按本次观察表达，前后变化采用材料明确的旧认识作起点；可只有经历而无认知，不以数量或篇幅验收。真实结果见[认识增量实测](REVIEW_SIMPLIFICATION_AUDIT.md#认识增量提示真实测试)。

本轮实测仍将已有认识写成新的发现，核心语义验收未通过。复核同时确认：与旧认识一致并不自动代表没有增量，新的领域信息或具体约定可能是真实补充。评价应逐条区分新增信息、已有理解与推断，不能以删掉所有一致内容代替准确选择。
