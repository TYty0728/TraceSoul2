# 每日复盘：四步流水线

2026-10-30 按用户确认重写。本文取代旧文档中“观察、细节扩写、全天回望、全量认知、逐卡演化、榜单晋升”作为每日完成条件的设计。

## 执行语义

入口为 `Tools/Migration/DailyReviewPipeline.cs` 的 `DayBuilder.RunAsync`。记忆日仍为北京时间 04:00 至次日 04:00。

1. **切段提取事件**：读取当天未处理的私密对话，按会话、时间顺序分段，每段通常不超过 48 条或 16000 字。模型一次输出事件摘要和本段来源编号。摘要就是事件正文，不再逐件调用模型扩写。源消息保留完整内容；单条超过 64000 字会明确失败，不截断后声称处理完成。
2. **挑选事件**：按重要性选出至多 10 件，也可以一件不选。大量候选分批选择再合并，单次最多 30 件、16000 字摘要。已完成的批次选择持久化。程序将最终选择写入当天事件榜，无额外排序模型调用。
3. **形成或修订认知**：只读取入选事件对应的原始对话，召回相关旧认知。0.1.90起，明确配置JEV槽时采用下述LLM草稿与原生JEV决策；无配置的新日期保留生成操作包的路径，每批至多3条。原文仍是依据，摘要不替代证据。
4. **更新当前 runtime**：一次请求处理确有变化的身份卡和心里状态。固定人格与固定卡不可改写，卡片只能引用同 slot 的有效认知。空字段保持原状；不清空当前活动或关注。提交时检查卡片和认知依据；若实时聊天已推进主体版本，旧复盘不覆盖新的 runtime。

所有短编号均是请求内的 `1、2、3…`，不要求模型生成或抄写数据库 ID。格式和引用错误至多进行一次结构化纠正，然后明确失败；0.1.92起第4步结构/引用合格但正文超长时另走单字段压缩，见下节。空日不请求模型；没有入选事件不强行生成认知或心境。

向量编码由本地 BGE 完成，按内容哈希复用，保证新事件能被现有聊天召回。公开经历仍由独立受众隔离入口整理，不进入私密事件、卡片及 runtime 请求；这一边界没有改成混合材料。

## 0.1.92：提示长度留余量与第4步单字段处理

按用户要求，模型提示只给一个较低的字符硬上限，不同时给建议目标与程序容错上限。明确字符包含标点、空格、换行、数字、英文；普通中文与常用标点各计1，emoji等补充字符通常计2，按JSON解码后字符串计数。程序既有长度校验保持。

| 字段 | 提示词硬上限 | 程序上限（不作为模型输出预算） |
|---|---:|---:|
| runtime.narrative | 80 | 120 |
| runtime.mood | 50 | 80 |
| runtime.relationship_lens | 130 | 200 |
| 可更新卡片body、事件/认知summary | 400 | 600 |
| 认知scope、exceptions | 200 | 300 |
| 新主题name、definition | 8／160 | 12／240 |
| 主题正反例单条 | 60 | 100 |

数组个数单独明确：事件最多12项，入选最多10项，旧认知操作最多3项；每事件主题合计1～4项且新增最多2项；第4步cards合计0～4项、slot不重复，每卡cognition_refs为1～12个同slot不同编号。JEV单项草稿仍只有summary/scope/exceptions三个字符串。纠正提示沿用较低的正文上限，不重新把较高容错边界当作输出要求。

第4步先校验结构、可修改卡片与引用，再保存RuntimeDraft及上下文摘要。超出程序上限的字段独立请求压缩，每字段每轮最多2次；请求只含该字段原稿、当前稿、程序实测字符数与较低的max_length，只允许返回一个text字符串。合格字段和来源编号原样保留；禁止空白敷衍、混入操作字段及直接截字。失败保留草稿，明确失败保护，不无限补试或假报完成；正常调用继续计入256次总预算。

每个合格压缩结果立即保存检查点，但卡片/runtime仍在全部通过后同事务提交。断连、预算让出、提交失败可以复用合格草稿；来源、身份卡、认知依据或主体版本变化使相应旧草稿失效或拒绝提交。实时聊天已推进主体版本时仍不覆盖新runtime。旧日期无草稿时只补第4步，已完成JEV认知不重放。

验证：实际Migration覆盖124→123字符后局部纠正、标点/emoji与120/121边界、较低提示上限与实际容错、卡片及多个runtime字段先后超长、断连/预算续做、超长/空白/额外字段的两次上限、草稿缓存、身份卡变化失效及提交回滚。未调用真实Kimi或重跑生产整日，语义压缩质量仍需实际验收。

## 第3步原生JEV接入（0.1.90）

`JevCognitionReview.cs`按会话切段，再按每项认知最多16条证据的现有硬限制分批，每批最多3个串行工作项。LLM每次只生成summary、scope、exceptions三个正文字符串，不生成操作、目标、来源、类别或领域。正文格式最多纠正一次；草稿先保存，传输失败可续接，不重新生成已保存草稿。

原生JEV只回答程序提供的choice：新增/已有目标/跳过/待核对，已有目标再判断印证/修订/跳过/待核对。首版不开放weaken/retire。逐句判断支持关系，仅从支持来源对应事件的主题中选主题；支持关系不明确则待核对。0.1.90在相关主题超过4个时直接阻断，0.1.91改为下述有数量约束的选择。新认识选择程序定义的类别/领域组合；印证和修订直接继承目标类别及领域，印证还复用目标正文。程序绑定实际ID并执行现有校验，JEV不直接构造数据库写入。

空草稿需要JEV确认无剩余变化，不能仅凭LLM空字符串标记完成。已处理工作项包含草稿、状态、操作和绑定来源，供后续判断去重。每批仍按最多3项的认知选择预算完成，不意味着穷尽原句中所有可推导认识。调用数量比旧操作包增多；每次实际JEV请求与LLM共用256次派发上限，原生JEV无自动重试。服务失败立即退出，语义待核对可继续独立批次，但整日保持未完成并进入失败保护，需检查后手动续做。

检查点记录草稿、有效答案缓存和单项状态；正式认知与committed进度同事务。来源/身份变化时拒绝提交，候选认知或主题变化时拒绝旧决策，下次重建未完成项。待核对答案不缓存。正在续做的JEV日期冻结来源快照，迟到原句下一轮处理。已完成项不重放，未完成项的合法答案只在相同输入与版本下复用。

首次进入第3步固定CognitionEngine。JEV检查点Version=2，来源戳带jev-v1前缀，旧程序会拒绝继续该检查点。旧四步已成功的前两步和认知来源进度保留；已固定JEV的日期缺配置或选择聊天型供应商时明确失败，不回退生成操作包。新版本安装后，现有原生JEV槽会在下一次手动/正常派发复盘时生效；安装本身不解除暂停或触发复盘。回退二进制不能直接续接部分完成的JEV日期。

验证：实际Migration模拟回归覆盖新认识、已有空类别/表达习惯继承、无效候选、传输失败、重开复用、事务回滚、独立批次待核对、原件/身份变更、迟到消息与共享预算。真实typesafe/jev-1.14合成新认识场景5次决策通过，上报USD0.000148806；草稿由测试桩生成，未发送生产对话。首轮试验曾出现四领域全选和结束判断待核对，改为组合候选并补足已处理结果后通过。单一场景不代表真实整日语义验收，前两步和第4步尚未迁移JEV。

### 0.1.91：相关主题超限后的有限选择

保留逐主题的相关性判断与其缓存。相关主题超过4个时，追加原生choice，每轮选择一个最核心且未被已选主题覆盖的主题，或明确结束/待核对；程序最多接纳4个不同ID。最多18个主题加done/defer构成一题，超出时分组各选一个，再比较各组优胜者，之后从全部剩余候选进入下一轮。每页早停只代表该页无合适主题，不跳过其它页；达到4项为程序预算结束。单页最多追加4次选择，20候选全选到上限时8次，全部计入既有派发预算。

## 提交与续做

- 新进度只存主库 `plugin_documents` 的 `daily-review` 文档，按天记录来源快照、已提取来源、事件、批次选择、已处理认知来源和 runtime 完成标记。
- 每批事件与对应进度在同一事务提交；认知与其进度也在同一事务提交；身份卡、runtime 和第四步进度同样原子提交。事务失败不能留下“写入了数据但未记录进度”的半成品。
- 只按本轮快照中确实处理的 Moment ID 标记 `built`，不使用整日范围 UPDATE。过程中到达的新消息留给下一轮，预检不会用旧的 done 状态遮蔽迟到消息。
- 不再以 20 分钟总耗时让出，也不再由 Host 在 30 分钟强杀子进程。每轮最多 256 次逻辑请求，达到次数上限才保存进度、一分钟后续做；单次复盘请求最多 600 秒。服务停止或任务取消仍终止子进程并保留检查点。
- 连接异常、超时和 HTTP 408/429/500/502/503/504 使用统一的网络保护：整轮共用最多 2 次补试，分别等待 5、10 分钟，中间成功不补充次数。首次网络失败后 30 分钟只作为**再次派发补试请求**的窗口，已发出的请求仍可正常完成；休眠越过窗口后不会补发。次数或窗口耗尽后明确失败，交由日构建保护暂停，须手动恢复，不自动循环。
- 复盘供应商内部重试关闭，避免与上述额度相乘；保留业务层至多一次结构化纠正。鉴权/余额、Codex登录或安装、JSON/字段/来源校验及调用方取消不进入网络补试。成功恢复的瞬时网络错误不提前上报为最终失败。
- Codex 本地桥接推理上限为 540 秒，running 去重保护延长到至少 600 秒，成功缓存仍为 10 分钟。私有桥接需要同步更新源码才会采用新上限；服务器软件更新不会自动替换用户电脑上的桥接。
- 原始来源或身份被修订时，旧快照不能静默复用。历史尝试保留，不把新一次成功伪装成过去没有发生过错误。
