## 分工原则

模型负责理解眼前的交流、形成表达和行动意图，以及必要的语义判断。程序负责已知的上下文、运行流程、可靠记录和执行反馈。长期理解从经历与反馈中提炼，重要变化再进入身份摘要；用户设定的初始人格保持其既定归属。

减少模型必须作出的判断与重复填写，是本轮的衡量标准。只有字段换名、移入更深的对象或改成同样数量的 type，仍然没有完成这项工作。

| 内容 | 主责 | 边界 |
|---|---|---|
| 回应内容、表达方式、主动联系意图 | 当下模型 | 收到需要回应的消息仍须回应，内容和可用模态自主 |
| 需要查什么、想采取什么行动 | 当下模型 | 目录提供当前能力；程序检查参数、权限与预算 |
| 调用标识、身体路由、次数、重试和去重 | 程序 | 保留内部调用身份与真实回执；重试不能重复产生外部效果 |
| 时间、发言者、会话、原始对话与工具结果 | 程序 | 自动留存事实来源，无须模型复述后才算记录 |
| 已受理、进行中、成功、失败 | 程序及设备回执 | 模型决定如何回应反馈；记录以实际结果为准 |
| 此刻的新感受、值得保留的注意 | 当下模型按需给出 | 简短且可省略；已有状态继续存在，注意年龄由程序维护 |
| 明确约定、纠正与目标含义 | 当下语义理解 + 程序保存 | 当场生效；身份来源、原始证据与存储版本由程序维护 |
| 默认唤醒、到期处理、任务存续 | 程序 | 模型只在有具体意图时调整安排，决定休息仍属于主体选择 |
| 反复出现的偏好、关系变化、长期自我认识 | 后续整理 | 有来源、可修订；不把单次行为自动提升为规律 |

## 现有根字段的处理建议

| 现有字段 | 精简方向 | 源码与迁移注意 |
|---|---|---|
| step / reply / actions | 本轮 type/value | reply 提交正文，action 提交调用列表，wait 结束当前处理；行动后仍可继续判断 |
| refine | 专项表达加工时才出现 | 当前确实驱动额外模型调用；迁出常规开关时须保留明确的专项入口 |
| mood_changed | 程序计算 | Agent 的 Normalize 已按实际 mood 字段推导 |
| state_force | 程序执行来源优先级 | 当前会传入生活状态更新，退出模型输出时须保留来源冲突规则 |
| speak_center | 从常规模型输出退出 | 当前仍参与表达与自动表情上下文；须改用实际表达等已有信息，不能当作无消费者直接删去 |
| heartbeat_intent | 按需的本次意图，避免与其他感受重复 | 它是当前主动联系意图，不等于下一次安排；保留有价值的主体内容 |
| affect / mood / inner | 按需的感受记录，重新审阅必要结构 | affect 当前承担跨环境的概括情绪；mood/inner 可含私人原因。仅合为自由文字会损失隐私边界，字段退出须有对应设计 |
| attention / attention_links | 一条关注及其可选依据 | 模型选择关注的意义，程序维护期限及来源；记忆关联可按需而非每轮填引用 |
| today / new_fact | 原始记录自动保留；语义提炼按需/后续处理 | 当前分别供当天轨迹和今日新识消费；迁出前须接通这些视图，直接停写会丢失已有可见信息 |
| scene | 按需记录共同文字场景的变化 | 与实际位置、设备状态保留归属区别 |
| location / activity / activity_detail | 合并生活状态入口，以真实来源优先 | 程序可归集设备和能力反馈；缺少来源时不能靠规则推断真实生活 |
| goal_updates | 按需提交明确的约定或目标变更 | 内容、范围、改口和完成含义仍需理解，来源及校验由程序承担 |
| next_heartbeat_minutes / next_heartbeat_plan / sleep | 按需提交后续安排 | 默认延续由调度器负责；本轮 wait、安排未来醒来与休息停止自醒各有不同效果 |

## 嵌套参数的处理建议

行动只需表达所选能力及其业务参数。call_id 拟由程序生成并贯穿回执、纠正和重试；body_id 已可从能力绑定补齐。group_id 当前有分组与执行记录消费者，普通独立行动无需填写，确有组合意图时交给明确的组合能力或进阶结构。purpose 可供特殊业务使用，不要求每次另写一份行动理由。

arguments 拟使用原生 JSON 对象；协议适配层按能力参数类型校验，再转换为当前插件 name/value 字符串形式。对象、数组、数字和布尔值无需模型手工进行第二层 JSON 转义。转换应保留原值含义，不依赖任意 ToString 或按逗号分割。

目标记录中的 ID、来源消息、版本、保存时间和到期计算由程序负责；模型保留对内容及范围的理解。程序不能仅因当前发言者是用户，就把模型自己产生的愿望认定为用户要求；目标完成也需要对应结果与目标含义相符。已有 source/evidence_quote/id/horizon 等字段应分别设计替代来源，不能整组无条件删除。明确时间可规范化，含糊时间仍保留不确定性。

## 候选形态与执行顺序

普通回复：`{"type":"reply","value":"准备说的话"}`。需要执行时，type=action，value 为能力与业务参数列表；需要同时记录必要变化时附可选 updates。每种 type 有确定的 value 结构和具体错误提示，非法输出不触发外部执行。updates 的最终类型清单待按上述职责进一步收敛。

程序先校验整份提案，绑定真实事件与来源，再保存有效约定及状态增量；随后执行动作或发送表达。动作结果回到下一次判断，已保存的变化无需重复填写。当前阶段内的重试沿用同一执行身份，已完成动作按回执续接。发送失败、设备受理与确认完成分别记录。

省略意味着沿用已有状态；清空要有明确且按类型定义的写法。普通回复无需填写全套状态、重复解释为何开口或估算下一次心跳。这里不新增每轮固定的额外总结模型；后续规律总结沿用按经历整理的方向，具体机制另行打磨。

## 实施验收边界

- 新协议与内部状态适配、续推视图、能力参数、纠正说明和提示示例共同迁移，旧名称不通过其他注入入口重新出现。
- 保留只有图片/语音的回应、多行动后继续判断、用户入站回应、后台安静、休息和重新唤醒。
- 验证同轮状态继承、明确清空、失败后存续、跨环境隐私、目标证据和执行去重。
- 程序自动记录接替 today/new_fact 等入口时，验证历史、当天视图、召回和夜间整理仍能取得真实经历；原始记录与语义摘要分别处理。
- 功能保持与减负需分别验证：离线检查证明流程和数据完整性，真实使用观察协议错误、重复填写及表达质量；当前没有证据量化模型负担下降幅度。
