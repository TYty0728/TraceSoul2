## 启动

先使用原有 `Start-Panel.ps1` 启动电脑桥，确认 `/api/health` 不是预览进程。SSH 工具单独依赖 `Tools/SensoryBoard/requirements-remote.txt`；不要求服务器或主容器安装 Paramiko。远端宿主需有 Python 3、Docker、`ss`，并允许该 SSH 账号无交互运行 `sudo python3`。目标为 Linux Docker 容器。

在仓库外受限私密目录保存 SSH JSON，包含 `host`、`username`、可选 `port`，以及 `password` 或 `private_key_path` 之一。不要将内容放进命令行、日志或源码。首次使用前通过可信来源核对 SSH 主机指纹并保存到 `known_hosts`；工具拒绝未知或变更的主机密钥。

```powershell
python Tools/SensoryBoard/remote_tunnel.py `
  --connection-config <仓库外私密目录>/ssh-connection.json `
  --container tracesoul2 `
  --state-file <仓库外运行目录>/tunnel-state.json `
  --stop-file <仓库外运行目录>/stop.request
```

默认电脑桥与容器桥端口均为 5089，可通过 `--local-port` / `--remote-port` 同时调整为相同端口，以保留桥的HTTP Host校验。远端 Host 的桥地址应与容器端口一致；当前默认 `http://127.0.0.1:5089/` 无需修改。进程保持运行时连接有效；Ctrl+C 或 SSH 断线会关闭临时监听。工具不安装开机服务、不重连另一容器；容器重建会停止隧道，核对目标后重新启动。

隐藏运行时可创建指定的停止文件，请求有序退出；再次启动前移除旧停止文件。状态文件包含进程号和最近心跳时间，不能只凭旧的`ready`文件判断在线。应用层每5秒双向确认；电脑20秒没有收到回应或服务器25秒没有收到确认，会结束连接，避免SSH TCP尚未断开时永久保留旧监听。

SSH 反向转发只绑定宿主回环的临时端口，工具核验实际监听地址，拒绝放宽绑定的 SSH 配置。远端辅助进程只在目标容器网络命名空间创建 `127.0.0.1` 监听，然后回到宿主网络连接 SSH 转发。它不修改 Docker 端口发布、容器环境、Host 程序或防火墙。命令输入 EOF 是清理信号，停止电脑进程会释放两端隧道；已由真实断开复验。

本轮桥的55项Python检查及隧道3项检查通过；隧道检查覆盖半关闭后完整响应、空闲连接释放，以及端口不一致时在读凭据/联网前拒绝。真实链路另验：远端容器健康/设备握手可达，错误Host/Origin返回403，重复启动拒绝且原连接保留，有序停止与强制退出后监听均释放；独立临时端口保持SSH在线但停发应用心跳，26.85秒后辅助进程退出并释放监听。随后恢复正式隧道，未重启服务器。以上不包含实机长时间通话、语音中的断网、屏幕外观或冷启动自动恢复验收。

## 配置与验收

SSH 就绪只表示网络可达。用目标服务器已登录的 WebUI 检查当前 Soul，显式配置 WXXZ 语音，并确保本人声纹位于该角色的 `wxxz/` 下。已有本人档案可私密复制并核对摘要，不修改原件或降低匹配门槛；不要复制整套本机角色或把两个 Host 当作已同步。语音使用该角色已配置的服务及音色，不借另一供应商的 Key。

先建立会话并进行固定句的屏幕/播音测试，再由用户明确开启通话或触屏控制。开启触屏授权本身不采音；按开始后才监听。终止、断网和重启后的行为继续遵守 [触屏通话](WXXZ_TOUCH_CALL.md) 的租约与取消契约。
