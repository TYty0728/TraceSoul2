## 2026-11-06：程序主导的LLM与JEV复盘协作方案（规划）

用户在多次复盘校验失败后提出改变方向：LLM与JEV结合，由程序保证稳定可控。本节记录当时的整体实施建议，第3步的实际落地范围以上节为准。承接10月21日有限决策建议，新增明确的操作构造、单项工作队列及迁移边界。规划时停止0.1.89发布并保留本地补丁及标签，后续在0.1.90合并既有修复。

### 1. 目标与当前基础

现状：DailyReviewPipeline要求生成模型同时输出认识、操作、目标编号、来源、主题、身份类别和领域；一次纠正重新生成整个列表，错误容易从一个字段转移到另一个。0.1.88补了主题映射，后续仍出现reinforce改变目标类别、纠正变成4项等问题。

已核对源码：DecisionsClient有choice/noul/score及答案候选校验，LlmProviderStore有CreateJevDecisionClient，Migration项目已编译包含这些源文件，但四步复盘尚无调用。现有适配使用已实现的OpenRouter Decisions直连/专用中转路径；不是任意聊天JSON即可充当原生JEV。服务当前可用模型、账号权限、质量与时延需实施时另行核验，过去三个模拟场景不能作为复盘能力证明。

目标：程序可保证合法引用、权限、身份约束、次数上限、事务和幂等；语义正确性仍需证据、模型判断和回放评估，不能承诺模型不再误判或服务不再失败。

### 2. 三方职责

| 层 | 负责 | 不授予的能力 |
|---|---|---|
| LLM | 阅读原始材料，提出事件/认识草稿，解释条件与反证，撰写当前卡片和叙事 | 任意数据库ID、事务操作、角色类别迁移、重试/调度、正式状态直接写入 |
| JEV | 从本轮合法候选中判断支持/不足、同义/印证/修订、取用主题、选择优先级 | 生成任意操作参数、捏造来源、创造永久目标、绕开程序保护 |
| 程序 | 来源与受众隔离、候选构造、编号绑定、类别继承、工作项预算、版本检查、执行与恢复 | 把合法格式当语义正确，或擅自把含糊内容认定为事实 |

LLM仍保留深入理解与提出新认识的职责；JEV不接管整个Soul的思考，不新增第二份主体状态。所有结果归入同一Soul权威版本线。

### 3. 主流程与不可自由组合的操作

程序冻结原件及相关版本 → LLM产生只读草稿 → 程序检索候选、建立具体合法动作 → JEV选择或保留待核对 → 按需由LLM成稿 → 程序检查、事务提交。

每个候选动作由程序预先绑定：工作项、证据集合、目标认知与其修订号、合法主题、类别/领域、效果及幂等键。绑定信息留在程序，不由模型回传。JEV只返回本轮选择键；执行前重新核对候选版本和权限。对一个目标的多项冲突操作串行处理，不能将各题独立选择拼成互相矛盾的写入。

例：本轮提供“印证认知4”“修订认知4”“新增独立认识”“依据不足，待核对”等合法候选。选印证认知4时，程序继承它的expression_habit及领域约束，模型不再输出identity_slot或domains。主题只在已判定证据支持的事件主题中选；认识条数由队列控制，不由模型数组长度控制。首版不开放retire等破坏性操作自动执行，后续单独评估。

新认识没有既有类别可继承时，程序提供现有本体中合法的类别/领域组合供判断；允许保留未归类草稿，不能所有新认识强塞relation。主题生长仍保留：LLM可提出主题定义草稿，程序做同名/结构与权限检查，JEV判断复用或确需新增，再由程序分配ID。不能为了可控而固定死主题体系。

### 4. 四步如何改造

1. 提取事件：程序切分并编号原句，构造可追溯材料包；LLM只提一个有边界的事件草稿，JEV对支持该草稿的候选原句作有限判断。程序保存精确来源子集。材料包与草稿关联只是来源范围，不等于包内每句都支持该结论；材料不足返回待核对。优先复用已有来源/事件，不让程序凭字符串相似直接判事件相同。
2. 挑选：对已有事件做有限优先级判断，程序执行数量预算与稳定排序。榜单未入选不删除原件；日常印证仍有独立处理机会。最多10件等既有上限首版保持为调度参数，是否改变另行评估。
3. 形成认知：先落草稿，再召回旧认知；JEV选择具体关系与目标，程序构造动作。印证尽量不重新生成正文；修订才让LLM写完整新正文及必要范围/例外。一次生成一个工作项，不让LLM再生成带任意target_ref/identity_slot/domains的整包写入。首个试点仅替换这一阶段，前两步使用既有检查点。
4. 更新卡片/runtime：程序按合法类别分组已提交认识，提供受支持的更新目标。JEV判断保留或更新，LLM只生成对应正文。固定卡保护、相关依据、当前主体版本由程序绑定。保留同一Soul runtime的提交互斥，生成期间实时状态变化则重新规划该项，不覆盖新状态。

认识正文、证据是否真正支持、范围是否夸大仍是语义问题。JEV要看到必要原句、上下文、旧认识和反证，不能仅审核LLM自己的摘要。协议合法或两个模型同意都不是事实证明。

### 5. 单项失败与完成语义

新增程序拥有的工作项状态：pending、drafted、decided、committed、deferred、failed；另存完成原因以区别明确无变化与依据不足。阶段与日期汇总从工作项推导，不能用“部分成功”冒充整日done。

每项草稿、候选快照和有效决策可复用；事务将正式写入与committed检查点一起提交。来源、目标或提示/契约版本变化时使依赖结果失效，避免拿旧决策套新上下文。相互依赖项目等待，独立项目可继续；整个模型服务不可用、权限异常或数据库错误仍应暂停相关批次，不能每个条目各自重试形成请求风暴。

不合规正文可有一次限定重写，仍失败保留草稿待处理；不截掉第4条、盲截长正文或自动把类别改成relation。语义不确定、JEV缺配置/不可用、请求失败分别标记，不能当“无变化”。原生JEV客户端当前不自动重试，若增加调度层重试必须共享整轮额度与冷却，不叠加供应商重试。首版保持已有网络预算，新增选择/生成调用都计入同一总账。

每项最多一次自动局部语义修复的具体上限为建议。只有独立合法操作执行；保留依赖关系，涉及多项共同不变量的操作同一事务提交。原始来源的built状态需等其依赖工作项全部明确处理，deferred来源不能被吞掉。

### 6. 迁移与落地顺序

A. 先做程序层操作构造器、工作项状态机、幂等提交和故障注入。将现行检查集中为可构造动作的前置规则；无模型也能验证不越权、不串类、不重复写。首版形成认知动作只保留已验证的create/reinforce/revise及defer/no_change，不静默处理不支持操作。

B. 抽出复盘决策接口，适配现有CreateJevDecisionClient。问题与选项数量服从本地客户端上限；采用小批命名题，候选分阶段消歧，避免操作×目标×类别的组合爆炸。共享有限调用额度，不机械地给每个字段增加一次JEV请求。只有一个合法执行结果且无需语义判断时直接由规则处理。

C. 同材料旁路对照第3步：旧流程与新流程都只写隔离副本/报告，真实调用须显式启用。涵盖当前故障的脱敏结构、空类别、多个相似旧认识、同词异义、主观感受/计划/已发生区别、日常印证、反证、材料不足、模型拒答、选项顺序变化。先证明语义质量，再决定接管权，不能只通过模拟测试就上线。

D. 在本地现有角色的受限快照副本验收后，按日期固定pipeline_version切换新流程；旧已完成结果保持。未完成日期保留来源快照、已提取事件、选中事件及已提交认知，显式映射剩余工作项；建立迁移账本和去重键，不删旧进度重跑整日。不能可靠映射时保持旧流程待处理并报告，不猜测迁移。同一天只有一个执行器；回滚程序不能抹掉新流程已提交结果，应读迁移账本阻止重放。

E. 第3步通过后，再迁移事件提取/选择与卡片runtime；最后评估日常Agent工具决策、背景感知与任务推进。明确用户发言仍直接进入主模型，QQ与WXXZ入口不各自产生主体状态，不把JEV变成强制逐轮聊天前置。

### 7. 验收与成本

硬性验收：任意/缺失/重复/迟到答案不产生非法引用；既有类别不被印证改变；并发与重启不重复写；来源修订使旧结果失效；一个项目的失败可解释且不吞其它项目；整日完成与待处理状态一致；事务中断可恢复。

语义验收：人工标注正确合并/错合并、漏掉新认识、重复新建、错误印证/修订、依据不足弃权以及日常沉淀遗漏；比较选项顺序与多次运行稳定性。先约定回放集及可接受错误，再准入生产；高置信度不能代替正确率，阈值由回放校准。新流程不得以“总是defer”或全部no_change换取结构零错误。

成本按草稿调用数、JEV判断批次、需成稿条目、实际修复次数分别计账，同时记录token、耗时和待处理比例。预计会增加部分判断调用、减少整包重试，但净费用与延迟未实测，不能先承诺更省或更快。所有诊断只留脱敏统计，原件与模型输出留在受限运行数据中。

本次只完成源码核对与方案文档，未改产品代码、配置、正式数据或调度，未调用JEV/生成模型、发布或部署。

## 感官终端接入原则（规划）

- 服务器作为设备会话、有效观察、角色上下文和决策的权威来源；电脑作为识图、听写、TTS worker，主动连接服务器，按任务返回带来源/时间/版本/置信度的结果。迁移 worker 不改变 Soul 的决策位置。
- “广泛使用”指在多个语义判断环节引入 JEV，不表示每帧图片/每块音频都调用，也不必先建立多个独立代理。先共用明确配置的 `jev` 槽，按环节区分输入/输出契约与验证；不同模型分工待实测质量与延迟后再细化。
- 首批考虑被动场景变化的注意判断、补充观察/工具/表达的行动选择、执行反馈后的调整。普通有效用户发言仍沿正常入站回应约束处理，不允许被动事件过滤吞掉发言。
- 统一服从同一 Soul 的权威状态；高频 JEV 只接收与当下有关的精简事实和约束，不全量注入身份、关系、记忆。需要这些材料的判断交给主模型。已有决策迁出一个环节时，同时停用该环节的旧入口，避免双重行动；具体路由、权限和状态提交由程序完成。
- 注意判断新增阶段也计入全轮调用/时间预算；被动观察按变化合并。决策带上下文版本，执行前核对新事件和取消状态，不能让迟到结果作用于已经变化的场景。
- 先进行无副作用回放与只记录建议的真实模型对照，再逐项启用执行。记忆整理、身份复盘及相机轮后机会另按已有规则迁移，本阶段不以“增加 JEV”为由自动改写它们。

项目内部 `jev` 是决策用途槽，用户指定的实际候选服务为 TypeSafe Jev 和 OpenAI Decisions，原生协议适配状态见下节。服务器统一发起模型请求并掌握执行权，所选模型可由供应商 API 承载，不等于必须在服务器自托管该模型。感官终端完整部署与阶段验收仍在工作区草案中维护，将随终端实现另行提交。

### 0.1.46 的配置入口与能力

配置入口是 TraceSoul 主控制台的「大脑 · LLM」，不是开发板 USB 控制页。先在供应商管理填写接口类型、Base URL、Key 并添加实际模型 ID，再到默认用途槽选择 JEV 并保存。目前支持项目已有的 OpenAI 兼容聊天协议与 Gemini 原生协议；特定服务是否兼容须按实际文档核对。此处只选择模型，尚无 30 秒/5 分钟调度开关。

在 WebUI「大脑 · LLM → 默认用途槽 → JEV（决策）」选择已有供应商的文本模型，点击「保存槽位」。可与聊天使用不同供应商/模型，也可明确选择同一个模型。留空禁用；旧配置无需迁移。

- 槽名为 `LlmSlotNames.Jev`（`jev`），持久化在现有模型配置中。
- `GET /providers/slots` 返回 `jev: { providerId, model }`，公开投影不包含 Key。
- `PUT /providers/slots` 接受相同对象；空 `providerId` 清空，省略 `jev` 或传 `null` 保留原选择，兼容旧客户端。
- 删除供应商或所选模型会清空关联槽。`ResolveSlot("jev")` 与 `ResolveExplicitSlot("jev")` 均只使用明确配置，不按模型的用途标记自动回退。无 Key 返回 `null`。
- 宿主 `LlmProviderStore.CreateJevClient()` 创建隔离客户端，沿用所选供应商的协议、温度、思考开关、超时与代理；不使用复盘专用温度，不改变主对话客户端。
- 插件复用现有 `ILlmProviderDirectory`，先 `ResolveExplicitSlot(LlmSlotNames.Jev)`，再 `CreateClient(endpoint.ProviderId, endpoint.Model)`。未新增接口方法，不要求插件实现额外成员。

“配置完成”只代表路由可解析。当前 `AgentLoopLogic` 和相机插件仍使用既有流程；没有把 JEV 客户端自动挂入每轮聊天。

## 后续设计：高频轻量检查与按需深入处理

2026-10-15 在真实联调后形成 [首版决策契约草案](JEV_DECISION_CONTRACT.md)：关注事项 + 有效事实 + 回执作为输入，首版每轮一个原生 choice，从具体候选中选择等待、补充观察或唤起主模型。该文尚待讨论，不代表实现或用户已经确认所有细节；下面早期自由 JSON 输出建议以该草案中的原生答案与服务器元数据分离为后续方向。

以下类型、参数与调度均待实现。用户明确的节奏是静息约 300 秒、专注约 30 秒；精确预算与接口是实施建议。

```text
板端采集 → 电脑小模型 → 服务器有效观察与最终转写
                              ↓
           定时检查 / 被动关键事件 → 精简 JEV 判断
                                   ├─ wait：保持安静
                                   ├─ observe：补充允许的观察
                                   └─ engage_main：交给统一主模型深入处理
用户有效发言 ──────────────────────────→ 统一主模型
                                       ↓
                   按需加载相关上下文 → 思考、工具行动与表达
                                       ↓
                       程序执行、真实回执、权威状态更新
```

### 频率与触发

| 状态/触发 | 初始规则 |
|---|---|
| 清醒静息 | 约每 5 分钟一次 JEV 检查，即使没有新画面变化，也可检查已有关注是否到期。一次检查可以直接选择等待。 |
| 专注 | 约每 30 秒一次；必须有明确用户指令或主模型已提交的活跃任务/关注及有效期，完成、撤销或过期后回静息。画面里有人不自动等于专注。 |
| 有效用户发言 | 立即进入现有入站流程，不等下一个定时点，也不由 JEV 判定是否值得回答。 |
| 被动关键事件/执行完成 | 合并近邻事件后可提前检查；与定时检查共用去重和并发控制，避免同一事件两次唤醒。 |
| 休眠、手动暂停 | 停止普通定时检查，唤醒按既有明确策略处理；静息与休眠是不同状态。 |

间隔由服务器配置并执行，不让模型任意缩短。每个 Soul 的检查串行运行，处理一个具备明确受众与权限的环境快照；多环境不拼接私密内容。主模型忙时合并后台事件并等待其结束后的最新状态，不并发争抢执行权。错过的定时点不补跑；重启只安排新的下一次检查。具体事件合并窗口、请求超时与失败退避作为运行参数实测。

### 输入预算

建议常态 **500～2000 字符、完整文本请求上限 3000 字符**，符合用户“几百到几千字”的要求。此为初始预算，不是已实现指标；计数包括固定指令、动态内容、输出格式及字段说明，另记录实际 token 数，不能将中文字数等同于 token 数。高频请求不附原始图像/音频。

| 内容 | 内容边界 |
|---|---|
| 固定规则和输出约定 | 极短的职责、等待/补充观察/请求主模型定义与事实约束；稳定前缀保持稳定。 |
| 当前任务和模式 | 正在关注什么、为何专注、何时到期、当前受众与必要限制。 |
| 近期变化及仍有效事实 | 人物在场变化、物体变化、必要短转写，附来源、时间和不确定性；不复制历史流水。 |
| 最近动作与结果 | 未完成事项、实际成功/失败、是否已回应、暂时不可用的设备。 |
| 可选观察 | 仅当下可用的少数观察 ID 和简短用途，不塞入完整工具目录或大段参数 schema。 |

不默认注入整个人格档案、身份卡、关系史、长期记忆召回、完整聊天历史或每帧识别清单。服务器直接从结构化状态选择材料，不为每次检查额外调用模型写摘要。必要约束由服务器保留且执行时再次校验；涉及关系、价值判断、记忆解释或信息不足时，交给主模型读取所需材料。这样共享同一 Soul 的状态，不需要高频重复加载全部人格。

超过预算时优先移除过时、重复和低价值观察，保留关键约束、当前任务与真实回执；按完整条目裁剪，不截断 JSON 或事实句。仍装不下时显式报告上下文不足，交给主模型或等待，不能悄悄丢掉必要约束。新感知缺失时保留“未知/离线/已过期”，不将旧画面当成当前事实。

### 最小结果与权威边界

早期候选接口为 `IJevAttentionPlanner.DecideAsync(JevAttentionRequest, CancellationToken)`，尚未实现。原生协议明确后，不再要求模型生成带 reason/evidence_refs 的自由 JSON；建议由原生 `answers.next_step.choice` 选择本轮具体候选，服务器绑定环境、相关状态版本、来源引用和具体观察参数。完整输入输出与关注事项见 [首版决策契约草案](JEV_DECISION_CONTRACT.md)。

`observe` 仅能请求当前会话已允许的补充观察，不自动开启已关闭的摄像头或麦克风，不发送文字/语音；`engage_main` 只提交一次核心处理请求，不直接代写回复、人格、记忆或任意系统提示。程序核对引用、能力、上下文版本、请求有效期和已处理事件，执行后登记真实回执。主模型继续拥有完整的思考、行动与表达能力；不把它缩减成润色器，也不让两个模型同时决定同一动作。

“广泛使用 JEV”后续可扩展到任务进展、观察充分性、工具结果分流等有边界的判断，各环节分别给短输入与可验证输出。涉及复杂任务规划时按需调用，不把完整工具参数和全部记忆带入每 30 秒的检查。是否迁移拍照等已有语义判断，单独确定唯一入口与验收；现有相机轮后机会和镜头规划暂时保留。

### 失败、诊断与实施顺序

- JEV 未配置时不启用新检查，保留现有主模型流程。调用失败或输出无效时不执行动作；有界纠错与重试计入同一调用/时间预算，持续失败退避并报告，不悄悄改用其他模型。
- 决策返回前有新发言、任务变化、暂停或离线时，重新检查版本并丢弃失效建议。已受理的动作不重放；受理/运行中不等于已经看到或听到。
- 记录触发来源、模式、下一次检查、输入字符数/token、耗时、结果、校验失败和实际回执。普通日志不含密钥或完整私密上下文；控制台可解释为何唤醒或保持安静。
- 先实现精简输入构造、预算与结构校验，用模拟时钟/模型检查 300/30 秒切换、到期、事件合并、暂停、重启、慢响应、超时与不重复执行；再做只记录建议的真实模型对照，最后接入核心处理请求。模型质量、时延和调用费用在真实对照时测量。
