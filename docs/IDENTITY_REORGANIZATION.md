# 身份重整

身份页的“重新形成身份认识”用于依据已有认知重新形成 self、other、relation、expression_habit。使用当前Soul的复盘模型、私密根会话和同一个身份存储；不创建人格实例，不进行聊天或发送消息。

## 使用

1. 选择身份卡。固定卡先解除固定。关联日期填写当前待整理的记忆日，也可留空只重整身份。
2. 点击“生成 / 继续候选”。这一步会调用复盘模型。后台任务返回后页面显示进度，刷新或重启后可继续。
3. 对照原卡、候选正文、认识变化、归并后的条件/反证/确定程度和认知引用，再点击“采用候选，写回此身份卡”。
4. 到记忆页续做关联日期。对已保存的核心/身份检查点，版本匹配的采用记录可以复用新卡，继续其他待整理项与收尾；不会重新补写已接受的卡。没有检查点或版本变化时遵循原有复盘检查，不能把一次采用当作整日成功。

## 语义与来源

第一阶段分批读取本项全部有效私密认知，按意义归并重复印证，保留不同对象、条件、例外、反证与不确定程度；只描述经历的材料另列并说明原因。每个输入ID恰好归入一组认识或细节，缺漏、重复、未知引用均停止。第二阶段跨批次综合认识，形成当前身份理解，并说明相对于旧卡的保留、加深、修订或放下。旧卡是比较材料，不要求逐句承接；正文不写成经历清单。

本功能生成认知的阅读归并与身份投影，原认知节点、经历及其引用保留，不自动修改认知图。它是人工触发的独立重整入口；普通夜间身份复盘仍使用既有流程。语义质量由模型生成并供用户对照判断，结构/长度通过不等同于语义已正确。

## 保存与并发

每批归并成功即保存，网络或成稿失败后继续时复用相同来源版本的归并结果；“重新生成”明确放弃本轮候选进度。候选不会覆盖原卡。采用时在独立数据库连接的写事务内复核身份、全部身份相关认知、输入证据与关联检查点，保存有来源的派生身份卡、旧卡历史和采用记录；不变成人工固定卡，重复采用不增加修改。生成和采用与日构建/存档互斥，采用还持有原Soul运行锁；聊天可以在候选生成期间正常进行，变化会使旧候选失效。

单批认知正文预算12000字符，单条超过预算或总认知超过5000/单项超过1000时明确停止；成稿材料超过120000字符时停止，不截取或静默漏掉来源。成稿维持300字符目标、600字符上限；单次执行没有模型纠错循环，失败后通过页面明确继续。底层API仍使用复盘通道既有的有限网络重试。任务20分钟超时，停机取消，错误提示不显示供应商原文。

## 验证

模拟模型覆盖完整来源分配、私密/跨角色隔离、预览无写入、来源历史、细节不可冒充认识、断线复用归并、候选过时拒绝、固定卡和重复采用。实际Migration入口覆盖 pending→重整采用→零模型调用完成；临时Host验证鉴权、后台生成、JSON数据、派生卡采用、幂等和版本冲突；网页脚本验证对照、安全文本展示、按钮和日期传递。没有对正式角色调用真实模型或写回资料，真实语义效果需要页面对照验收。
