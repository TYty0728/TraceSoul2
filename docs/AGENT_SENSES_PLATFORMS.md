# Agent、感官、平台与能力插件

2026-10-26 按用户确认重新收拢职责。它们是协作边界，不是每轮必须依次调用四个模型。

| 边界 | 负责 | 当前入口 |
|---|---|---|
| Agent 自循环 | 理解当下、回应、明确行动、目标与后续唤醒决定 | KernelLogic / AgentLoopLogic |
| 感官 | 将文字、画面、声音转为有来源的经历；视觉观察不冒充用户发言 | Moment 类型、识图、ASR、感知准入 |
| 平台 | QQ、WXXZ 等连接、身份/受众、会话及真实收发回执 | 平台插件、适配器、原轮目标 |
| 能力插件 | 相机规划/生成、检索等具体工作，返回结果 | 贡献目录与能力调用 |

所有入口仍是一份权威主体 runtime。平台没有独立人格；感官不规划主动消息；相机不决定人格或冒充拍摄设备实拍；内核统一判断输出目标与权限。平台专属操作（例如 QQ 空间和签名）可以依赖 QQ，通用能力不应因历史命名成为 QQ 子项。插件加载容器仍兼容 kernel/platform/organ，功能职责不靠新增开关或改一批名称来实现。

## 当下与轮后整理

2026-10-26补充：主动心跳与新消息使用不同动态入口。主动轮没有“尚未回复”的任务，在同次输出形成 `heartbeat_intent` 后才发文字或执行表达动作；缺失则安静结束并保留后续唤醒，不增加审核模型。旧计划到期重新评估，不能把已回复的用户发言再回答一遍。详见[Agent运行框架](AGENT_HARNESS.md)。这与下述关注整理分别负责表达选择和状态收尾。

普通 Agent 的回复/行动循环继续有界，最多四轮行动。关注和共同文字场景增加独立轮后收尾：回复完成后取得有界快照，使用复盘槽（为空沿用主模型）作一次 JSON 业务请求，失败保留原状态，不进入 Agent/工具循环、不外发、不重规划心跳。主提示取消这两项的例行填写要求，保留明确变化时立即影响行动的可选补丁及旧输出兼容。情绪、当下感受、实际活动、事件短句、新识和明确目标仍沿原链，本次没有搬动夜间认知/身份管线。

专用队列最多一份执行、一份最新待处理快照；连续输入替换尚未开始的旧整理。分析不持有对话锁；写回重新取得同一锁，并核对主体与内心两层版本。任何新轮次/复盘已更新状态，旧结果整份丢弃。重复关注保留原时间，六小时自然过期继续生效。只整理私密视图，公开输入不借此读取私人关注。没有启动时批量重写历史或在每次心跳之外另开自循环。

## 通用相机与平台输出

相机元数据显式 `PlatformId=""`，表示通用插件；`null` 才保留旧包按名字推断平台的兼容。旧 `qq.imagegen` 插件/能力 ID、数据目录、图库和配置继续沿用，但不再形成 QQ 启停依赖。

通用图片能力声明 `BodyIds.ReplyTarget`。目录和执行身份由内核绑定本轮已确认平台；`TracePlatformOutput` 只取该平台适配器，不查最近活跃 QQ、不跨端兜底。平台通过可选 `ITraceOutboundCapabilities` 声明能发送的媒体。OneBot 已声明图片支持；WXXZ 现有文字/声音/状态屏链路没有声明此通用图片输出，因此目前不会出现相机入口，不能把协议解耦宣称为开发板已支持照片显示。

图片生成继续走标准 Images generations/edits。失败返回真实能力结果，由 Agent 判断怎么回应，插件不自行追加一段错误聊天。自动配图机会、镜头规划、参考图和风格保留。页面将通用插件与平台分组分开。

## 验证边界

离线 `--turn-maintenance` 覆盖快照准备无模型调用、完成后清空、重复年龄/到期、重复提交、跨平台新轮先提交的迟到结果、格式失败无业务重试、取消，以及真实 Kernel 移交；相机以两种模拟平台验证目录绑定、发送、无媒体支持和失败回执。既有相机分享测试补齐真实环境目标。所有测试使用临时数据与模拟模型/适配器。

完整 ChatCheck、`--prompt-layout`、相机分享及轮后整理专项、Host/相机构建、runtime 页面脚本检查和 `git diff --check` 已通过。ChatCheck 保留既有24条相机上下文类型重复编译警告，Host/相机构建无警告。补充验收确认两平台即使会话编号相同，也不会共用配图计数或借用最近QQ会话。

本地源码改动，未修改正式状态、调用真实模型、发 QQ、重启或部署。Host、PluginApi 和相机必须配套构建/更新；不能只替换其中一个 DLL。语义收尾质量及实际用户体验仍需部署后观察。
