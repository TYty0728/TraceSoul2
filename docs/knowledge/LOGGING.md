# 运行日志规范

2026-11-03：整理统一Agent运行日志及控制台阅读入口。本地实现，尚未发布部署；不改事件、记忆或模型输出契约。

## 当前输出

网页事件流统一为 `日期 时间 时区 [级别] [轮次 编号] 阶段 ｜ 耗时 ｜ 必要细节`。没有轮次时省略轮次块，不再打印横线占位。耗时不足1秒用毫秒，其余用秒；保留模型名、能力ID、错误类型与HTTP状态等排障线索。示例为模拟数据：

```text
2026-11-03 10:00:00.100 +08:00 [信息] [轮次 abc123] Agent 继续行动 ｜ 步骤：1 ｜ 行动数：1
2026-11-03 10:00:01.350 +08:00 [信息] [轮次 abc123] 执行返回：网页读取 ｜ 耗时 1.25 s ｜ 状态：成功 ｜ 能力：web.read
```

`TraceLogFormat` 是共享文本格式器。`TracePluginServices.LogTiming` 的原四参数签名保留；新增 `LogDiagnostic` 用于高频内部过程。已有旧插件直接输出的 `[链路 ...]` 前缀由宿主兼容转换。SSE继续传原来的字符串消息，不更改订阅协议。

- 信息：输入、行动、模型请求、发送、轮次完成等关键进度。
- 调试：上下文块读取、状态面处理、内部落库及轮后通知等；移除逐模块开始/完成成对打印和缓存重复打印。
- 警告：需要注意的执行或状态更新失败。旧日志未声明级别时按阶段词作兼容分类，新入口可显式指定级别。
- 错误：模型请求异常等明确失败。调用方取消单独记为已取消，不冒充模型失败。

`running/accepted` 显示为进行中/已受理，不报告执行成功；返回 `failed` 的能力及状态更新也会显示警告，不能只依靠是否抛异常。上下文读取异常不再从finally打印成功。模型日志只显示编号、模型、耗时、字符数和Token用量，不抄写请求/响应正文。本地/后台输入完成及空闲生活新识日志改为字符数/来源，不额外复制内容片段。

已有Base64过滤与2000字符上限保留；换行、连续空白和ANSI颜色控制序列整理为单行。此处不是完整秘密扫描器；调用方仍不得把密钥、Cookie或原始敏感载荷作为日志细节。

## 页面与范围

日志页最新在前，可选常规、警告与错误、全部（含调试），支持轮次/能力名/关键词筛选。显式级别优先于“记忆”“缓存”等主题配色，失败不会被配成普通记忆日志。筛选仅隐藏行，不删除历史；服务器和页面各保留最近300条，调试也占此容量，不是长期审计存储。

ASP.NET控制台日志改为带时间的单行格式；命令行工具、Migration子进程及第三方独立日志仍有各自输出，本次没有替换全项目Console或修改宿主事件流的输出去向。

## 验证

- `ChatCheck --logging`：近期回放、慢订阅者容量、编码过滤、轮次/级别/耗时、旧前缀兼容、模型正文不进入计时日志、取消/失败，以及实际上下文异常和返回failed的状态更新。
- `ChatCheck --agent-loop`：真实Kernel的回复、工具、记忆、续推、状态和失败流程回归。
- `node scripts/tests/test-log-ui.cjs`：脚本语法、级别优先、筛选/轮次搜索、保留历史、300条上限与文本渲染。
- Host与ChatCheck/引用插件构建通过；使用模拟模型和临时库，未启动实际Host或向真人发消息。
