## 2026-10-22 结论与范围

用户确认范围是 TraceSoul2 控制台和 New API。针对 Node.js 2026-10-21 安全更新检查两台宿主机、当前容器和同机 QQ/NapCat 桥：两个网页主服务没有发现本次 Node.js 漏洞的直接适用运行组件，但 TraceSoul2 同机 QQ 桥存在旧运行环境及公网管理入口，需要优先收紧。

| 检查对象 | 观察结果 | 判断 |
|---|---|---|
| TraceSoul2 控制台 | .NET 8；容器进程为 sh/dotnet，应用端口仅绑定宿主回环；本机请求返回 HTTP200 | 当前网页请求不由 Node.js 处理 |
| New API | Go 主程序；运行容器仅 new-api 进程；宿主常见路径、已安装包和当前进程未发现 Node.js | 编译后的前端使用 JavaScript 不等于服务器运行 Node.js |
| TraceSoul2 宿主 | NodeSource Node.js 22.22.2，Brotli 1.1.0；未发现独立 Node/npm/pm2 等运行进程 | 版本落后于本次修复，应更新；本次未发现它承载网页服务 |
| QQ/NapCat 桥 | QQ 3.2.30-50969；二进制包含 Electron/40.0.0、Chrome/144.0.7559.60 标记 | 包含另一套内置运行环境，升级宿主 Node.js 不会替换它 |

官方公告包含 Brotli 解码越界写导致远程代码执行的 CVE-2026-111497，影响 Node.js 22/24/26 分支，修复版本为 22.23.4、24.22.1、26.12.1。它是独立于 PHP2Shell 的另一组安全更新，不能由“不运行 PHP”排除。

## QQ/NapCat 管理入口

- Docker 将管理端口 6099 发布到所有 IPv4/IPv6 地址；从检查电脑进行普通 TCP 连接成功，确认存在公网可达入口。
- WebUI 配置存在非已知默认 token 和登录限速；未读取或记录 token 正文。有鉴权不等于请求体解压发生在鉴权之后。
- 静态检查现装程序：WebUI 先注册 Express JSON 请求体解析器，再挂载带鉴权的 API 路由。现装 express 5.2.1、body-parser 2.3.0，后者的 br 分支调用 Node.js 的 createBrotliDecompress。未发送压缩测试、异常数据或漏洞利用请求。
- 上游 Electron 40.0.0 对应 Node.js 24.11.1。这是依据官方版本映射的推断，并非本次直接读到 QQ 的 process.versions；厂商是否定制或回移安全补丁尚未确认。因此不能直接宣称已可利用，也不能把此入口判为安全。

优先限制 6099 的公网访问，例如改为宿主回环发布并用 SSH 隧道管理，或在实际生效的网络边界仅允许可信来源；Docker 发布端口时需要确认规则确实覆盖容器流量。随后核实并更新带安全修复内置运行时的 QQ/镜像及兼容的 NapCat，最后更新宿主 Node.js 的对应分支。单独升级 NapCat 脚本或宿主 Node.js，不能证明 QQ 内置运行时已修复。

本次仅做读取和普通连通性检查，未改服务器配置、升级镜像、重启服务或操作实时数据库。没有进行完整入侵、管理员登录或密钥泄露审计；本结论不能证明从未遭入侵。备份校验也不替代漏洞修复。
