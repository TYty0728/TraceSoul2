# FishDemo 视觉参考核对

2026-11-03：根据用户提供的 FishDemo 两张截图、记忆银河/记忆面板独立包源码及完整架构说明进行静态核对。未启动对方核心、读取正式聊天库、调用模型或修改产品代码。动效与性能未在浏览器实测；以下区分源码行为与拟议设计。

## 已核对的实现

- 银河入口为 `01_记忆银河/01_记忆银河/code/galaxy/dsh-Memory-Galaxy/public/index.html`。使用 Canvas 2D、自写相机投影和 requestAnimationFrame，不依赖 Three.js；深蓝底、暖色中心、旋臂薄雾、轨道、低亮星尘和少量高亮节点形成层次。
- 银河标签只优先显示重要节点及选中/悬停项，并做矩形碰撞剔除；支持搜索弱化非命中项、类型筛选、旋转缩放、详情卡。双击钉住仅改变本次浏览状态。
- `export_galaxy.py` 对 active 记忆按重要度、近期性、实体度数排序，取前80条主星；另附身份、要求等节点。星图不是全量数据库。展示时应区分全库总数与当前展示数。
- 银河 `retention()` 使用指数公式计算视觉留存，时间滑杆是未来推演，不是历史回放或数据库遗忘结果。前端读取了 links，但所查 draw() 未遍历绘制这些关系；不能仅凭导出含 links 就认定已有完整关系图。
- 脑图入口为 `02_记忆面板/02_记忆面板/code/panel3d.html`。也是 Canvas 2D 投影，采用球面/类别布局、青蓝辉光、扫描线、轨道及粒子脉冲。spriteFor() 缓存辉光贴图。
- 脑图 activity 映射读取 life.activity 是否 chat；updateFires、updateSparkles、空闲触发及 newPath 包含随机选择。粒子不能被解释为具体记忆的真实激活链路。
- 脑图适配层用记忆正文是否包含实体名推导部分记忆—实体关联；buildGraph() 自动添加核心到各节点的展示边。因此画面中并非每条边都来自数据库中的语义关系。
- 面板存在“反思、沉淀、睡觉、维护”等按钮，但本包适配层的多数未实现请求回空成功；不能依据按钮存在宣称功能已接通。
- 银河子目录附带 MIT LICENSE（2026 Derpyu520 & 大肥鱼）。此记录不将该文件的覆盖范围扩展为整个交付包；实际复用时核对所取文件的来源并保留对应声明。

## 对 TraceSoul2 的适配判断（建议，尚未实现）

最值得借鉴的是“整体氛围 → 少量重点 → 点选详情”的层次，以及让同一主体的记忆和当下状态具有可感知的空间表达。

建议先增加只读的“心智星图”入口，保持现有管理表单职责。银河适合总览，证据网络适合选中后的局部展开；两者共享同一数据投影，不能另起可独立演化的主体或记忆库。

| 视觉元素 | 拟议数据语义 |
|---|---|
| 中心光核 | 唯一主体及当前 runtime 摘要，不表示身份卡是独立主体 |
| 四领域星群 | 我 ass、他 user、世界 world、关系 relation；多领域认知只保留同一ID，不复制成不同事实 |
| 可选星点 | 认知节点；低亮点可另表示经历，但必须在图例区分 |
| 大小/亮度 | 分别选择并明确标注重要程度、当前关注等含义，避免暗示亮度等于事实可信度 |
| 支持/反证/修订连线 | 现有证据和认知关系；展示辅助线使用不同样式 |
| 节点详情 | 正文、范围、例外、状态、领域、来源证据及版本 |
| 动画 | 默认仅表达氛围；只有取得真实召回/关注ID时才显示相应激活，并标明代表的阶段 |
| 时间控件 | 优先按实际产生/更新时间筛选；完整历史回放需另核对历史数据可恢复性 |

## 本项目已有基础与缺口

- `Tools/Host/Program.cs` 的 `/identity/puzzle` 已返回认知 ID、正文摘要、领域、状态、版本、范围、例外、来源 Moment ID/关系和分享状态，可作为详情入口基础。
- `src/TraceSoul2/Data/AgentArchitectureData.cs` 已定义 CognitionEvidenceRecord、CognitionEdgeRecord 等契约；认知领域与支持/反证/修订/关联语义见 `docs/COGNITION_PUZZLE.md`。
- 当前 `/identity/puzzle` 不是完整星图接口：未在该响应暴露全部认知间边、布局权重或实时召回链路。接入需新增有界只读投影，批量取节点/边/证据，按既有权限及版本规则过滤。
- 原始证据正文宜在点选后按权限加载，不为画背景预先传出全部聊天。数据接口应报告采样/截取范围、总数和版本，不能把局部视图当全量。
- 布局建议由稳定ID决定初始位置；选择节点时暂停自动旋转。提供搜索列表、减少动效、触屏与窄屏布局；页面隐藏时暂停绘制，按帧时间推进动画。大规模性能须实测，不从“Canvas较轻”推导无限扩展能力。

## 推荐实施顺序

1. 只读星图：四领域筛选、稳定布局、搜索、详情与证据跳转；以有限节点形成可理解的总览。
2. 选中节点后局部展开支持、反证、修订及相关关系，避免全量连线遮住主体。
3. 有真实运行事件可用后，接入关注/召回/夜间新增的短暂高亮；不得用随机动画伪装真实运行轨迹。

本次仅完成截图和源码对照。尚未验证真实浏览器交互、手机可用性、千级节点性能、完整包后端正确性，也未决定实际复用代码范围。

## 2026-11-03 后续：记忆运转机制核对

用户澄清本轮重点是记忆机制，并未决定改视觉；认可现有对话→短期记忆→睡眠归档/梦话链路，关注最终沉淀为切片、榜单与认知。前面的视觉建议不属于已确认实施计划。

以下相对路径以完整架构交付包为根；结论只覆盖所提供源码，不能代表对方未交付插件或服务器实际配置。

### 实际链路

1. `plugins/astrbot_plugin_dafeiyu_shadow/main.py` 在 LLM 请求/回应钩子观察文字，异步 POST `/ingest`；`self_core/shadow.py` 按非空 source_id 去重，直接将文字写为 memories 的 episode/surface，用户初始重要度0.6、assistant为0.4。并非先将多轮聊天总结为一段记忆；旧聊天导入脚本同样逐条写入。
2. `/ingest` 对用户文字另行更新状态，并依次尝试明确“永远记住”等核心记忆、提醒、待办抽取。`core_memory.py` 用固定触发语截取正文并去重；`working.py` 用正则识别未来事项。它的 working memory 主要是未完成任务，不等价于我们的当下感受切片。
3. `retrieve.py` 对 active 原文执行 FTS5/BM25 与中文2/3字片段LIKE查询，合并后按命中字片长度、重要度、时间排序。此召回函数未使用向量、实体关系遍历或认知推理。插件请求limit=3。
4. `context.py` 再拼接当前约束、时间/状态、核心记忆、待办提醒、相关记忆、近期用户记录、边界/偏好等。近期部分从最近8条active记录中过滤用户文字后最多取3条；core_memories默认取最早3条。相关原文单项截120字，近期项截100字；核心默认总预算1100字符，插件默认再截到900字符。实际值仍可能被配置覆盖。
5. 注入由插件的 inject 配置控制，默认回退值false；启用时加入 extra_user_content_parts 或旧版req.prompt。近期会话上下文另有默认保留24项的裁剪。代码能力存在不表示运行实例已启用。
6. `extract.py` 是固定实体词表匹配，并把同实体下相邻记忆连为co_mention，默认最多20条链接。所查入口是独立脚本，未发现接入每条消息或睡眠自动处理。共现不等于抽象认知。
7. `lifecycle.py` 的维护是权重衰减，低于阈值且达到最小年龄时标archived。事实、偏好、边界、承诺、关系、技能、protected和core层跳过；archived保留原文但退出当前常规召回。没有在该步骤生成摘要或替代性认知。
8. `runtime.py`/`scheduler.py` 的睡眠控制安静、唤醒时间与主动消息；插件亦维护sleeping状态。所查核心、适配器和脚本未发现睡眠触发日总结、分层提炼或梦话归档的链路。schema虽有summaries、tier、summary、reactivation等字段，但不能据此认定已接通长期提炼。

### 隔离验证

使用Python -B直接调用交付代码，SQLite为`:memory:`，所有文本均为合成测试内容；未运行服务、读取真实数据库或调用模型。

- 重放同一source_id得到同一记忆ID；写入为episode/surface、summary为空。
- recall后access_count和last_access仍为0。全包Python调用搜索只找到touch_memory定义，未找到调用；“召回加强/刷新访问”没有在此主链闭合。
- 创建45天前importance=0.6的记录，同一now连续执行两次apply_decay，结果约0.3→0.15且第二次已archived。源码每次将完整年龄的衰减因子乘到当前权重，重复维护会重复衰减；不能直接理解为稳定的45天半衰期。

### 与本项目的关系

该交付主要形成“可检索原文条目 + 明确核心记忆/任务等专项记录 + 实体共现图 + 衰减归档”。尚未发现与本项目相当的“全天经历和当时感受→回望/事件→认知修订→跨期榜单”的自动闭环。银河前80条排序属于展示选择，不是日/周/月/年记忆晋升机制。

本项目切片记录当时如何感受，夜间形成回望并据原始来源更新认知；榜单选择值得持续带入的事件与认知引用，不取代其底层原件。`LadderContextLogic`区分event/cognition，`DayLadderLogic`实现跨期选择。`NightResidueLogic`是复盘成功后的外显余温，不是长期存储结构本身。

可借鉴方向仅作为建议：当前状态优先于历史状态、明确承诺单列管理、记录实际注入内容以核对召回。应沿用本项目已有状态/目标/证据/运行审计机制核对缺口，不新建重复系统；不照搬正则全局结单、原文硬截断或重复年龄衰减。未改产品代码。

### 三句“牛肉面”到星星的验证

使用用户给出的三个合成例句“想吃牛肉面了”“牛肉面我喜欢加小葱”“我今天吃牛肉面的时候想到一个数学定理”，在临时SQLite按三日分别通过ShadowObserver写入，再运行实际extract_all与export_galaxy.main：三条均为episode/surface、importance=0.6。现有固定词表不含牛肉面、小葱、数学定理，抽取结果为零实体、零连接；小库导出三颗event星及三条message粒子，另有导出器默认主体星。全库情况下三条是否成为主星仍取决于前80名选择。

仅在测试进程内向food词表加入牛肉面后，重新抽取得到一实体、三条memory_entities关联、两条相邻记忆的co_mention边。导出新增一颗food实体星，正文只是“牛肉面 · food · 被记住3次”，weight=3；三条原始记忆并未合并或分别推断成愿望、偏好、数学认知。真实源码未修改。

lib/data.js的layout按强度、轨道设置及ID哈希安排位置，并非按句子语义向量聚类；不能把空间邻近解释为语义相近。当前export_galaxy最终输出stars/messages/meta，没有把数据库links输出；因此这里的数据库关系不能直接等同银河可见连线。脑图有单独的/graph数据路径。

验证断言通过，不访问外部API。初次临时目录清理遇到导出器未显式关闭SQLite连接的占用；后续释放连接重跑成功，临时测试文件已清理。
