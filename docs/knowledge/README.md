## 当前任务记录：2026-09-12

用户反馈：一条 QQ 对话有时收到多次回复；角色很少发照片。已确认照片期望是**聊天中自然主动分享自拍或生活照，不必每次索要**。

本次实现：

- QQ 收件箱在同一锁内按机器人、会话和 `message_id` 去重；重连重放、并发重复投递不会启动多轮。缓存最多 4096 条，保留 30 分钟，不按正文去重。
- 入站轮次和延迟图片优先使用触发消息的会话，防止后来入站改变旧轮收件人。
- 相机在心智动态段提供真实图片发送回执及之后的文字相处次数；至少 6 次文字回应后提醒重新考虑主动分享。这里只提醒，不强制选择 `image=有`，不新增 LLM 调用。
- 表情不充当照片回执；图片发送失败不再被改成成功；明确索图的补图只在最终回应运行，离场等待不重复补图；明确拒绝收图不触发关键词补图。
- 新增 `MindTurnPromptAppends` 共享钩子。相机只在可用目录包含生图器官时提供动态状态，卸载时移除。

证据边界：本机可见的最近聊天 dump 截止 2026-08-30；其中有连续多轮选择无图，也有选择有图的轮次。没有 9 月故障当时的完整链路，不能把所有多次回复都归因为重放。具体运行验收以新日志为准。

验证入口：`Tools/ChatCheck/QqDeliveryChecks.cs` 覆盖并发去重、消费后重放、不同会话/账号、无消息 ID、自身回显、旧轮收件人、图片/表情回执区分、动态反馈及卸载、拒绝索图、离场等待不重复补图。

交付验证：完整 ChatCheck、`--prompt-layout` 均通过；Host 与相机插件构建均为 0 警告、0 错误；`git diff --check` 通过。本机启动器所用相机 DLL 已备份后更新，Host 已构建。未启动 Host、未发送真实 QQ 消息；主动分享的实际频率与线上故障是否完全消失仍待真聊确认。机器路径与备份位置见外层工作区 `LOCAL_RUNTIME.md`。
