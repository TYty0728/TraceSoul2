# 开发板、QQ与同一主体（0.1.67）

## 路由约定

按用户确认：开发板只回应开发板发起的交流，QQ输入从QQ回复，心智自主醒来的联系始终通过QQ。同一Soul的身份、状态、生活、目标和入库使用一个权威实例，平台提供来源与收发目标。主模型只决定内容，路由由程序约束。

- 已确认本人私密输入使用同一根会话与原文窗口，保留每条Moment的真实平台、类型、发生时间及环境。公开输入保持受众隔离，从同一主体构造可见视图。
- 根runtime是感受、心情、关注、场景和睡眠/空闲的当下来源；生活和主体目标也使用根作用域。旧环境状态留作历史，读取不会恢复另一份旧当下，存储拒绝另存环境runtime。旧主体正文按版本原子接回一次。
- 前台回复绑定本轮真实来源；QQ或开发板离线时不改投另一端。异步执行回执保留原请求环境，不能因为后来收到其他平台消息而改目标。
- 自主时间唤醒和夜间联系读取独立的`proactive-qq`目标，仅接受当前仍绑定本人且已确认的一对一QQ环境。群聊、开发板、控制台不会覆盖该目标；升级首次覆盖旧根目标之前保全有效QQ目标。旧任务携带板端环境也改为QQ自主联系。
- 无有效QQ目标时停止自主处理，不改投开发板，也不先请求模型。解绑后旧目标失效。未配置QQ的本地控制台调试保留原模拟唤醒路径；这不提供开发板或其他真人通道的后备发送。
- 通过网页持续通话的明确输入仍沿其通话返回；自主心跳不能仅因电话在线就占用该电话。

Host各入口继续共用同一个SoulRuntime及运行锁。各平台的设备会话和发送回执分别绑定，不能将同一输入再送入本机另一份Soul。身份复盘、认知及日终回望继续使用0.1.65/0.1.66的流程。

## 远端接线与当前验收

电脑桥通过严格主机指纹校验的SSH回环隧道接入既有Docker Host，工具见[远端隧道](WXXZ_REMOTE_TUNNEL.md)。电脑负责设备TLS、识别、VAD、声纹及播放，远端角色负责心智、记忆与语音配置。本机不启动第二个Soul。电脑桥与隧道本身不会开启录音或触屏通话。

2026-10-23复核：实板USB可见、固件0.4.6、Wi-Fi已连接、麦克风暂停；电脑桥ASR/VAD/声纹模型就绪，远端容器网络命名空间经SSH完成同一设备hello。远端当前安装0.1.63，本轮未部署新版、录音、播音、调用正式主模型或发QQ验收消息。此前固定句音色已由用户确认，本轮未重复消耗TTS。

## 升级后的操作

1. 在远端现有WebUI完成版本更新并核对当前角色，电脑继续只运行设备桥和隧道。容器重建后需核对并重新连接隧道。
2. 在“身体与感官”连接WXXZ会话，确认既有本人声纹与该角色语音配置可用；不必重录或降低门槛。先保持触屏通话未授权。
3. 由本人明确在板端菜单选择“允许麦克风”，在远端WebUI点击“开始语音通话”。叫角色名字，听到应答后说一句短话；停顿后观察听写、本人识别及屏幕/语音回复。显式“暂停监听”结束采音，关闭网页本身不会停止。
4. 再由本人在QQ发送一句承接板端内容的话，检查只在QQ回复且上下文连续；随后在开发板承接QQ内容，检查只在开发板回复。网络及模拟测试不能代替这一步的实机验收。
5. 主动联系等待正常唤醒验证，只走QQ；无需额外制造验收消息或人为缩短唤醒周期。声纹拒绝、断线、停止、重启和触屏授权随后逐项验收。

模拟真实Kernel覆盖QQ→WXXZ→QQ、活动/情绪/关注/场景与目标接续、任意三个新增平台、旧快照不复活、一次性接回、公开过滤、关闭原文窗口及重启。新增主动心跳只发QQ一次且不触碰开发板媒体，QQ目标撤销后零模型请求，旧任务板端快照不抢目标；已有QQ目标升级及重启保留。通话明确输入、播放回执及挂断保护保持覆盖。
