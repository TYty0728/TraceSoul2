# 插件三层结构（大白话版）

> 2026-08-26 定稿，同日落地。这是「插件整合讨论」的结论，故意用大白话写，给以后接手的人看。
> 它是《ARCHITECTURE_ALIGNMENT.md》第 30 节的展开；两边冲突时以总纲为准。
>
> **落地状态**：三层定义、生命周期三规则、console 平台身份、game.session 升格、休眠过滤（目录 / 上下文块 / 后台轮询 / Moment 入口）、`/plugins` 休眠标记与分组展示——**已实现**（回归：ChatCheck/CoreCheck）。
> 仍渐进：`builtin.dialogue` 的内核残余职责拆分、星露谷/通用游戏从 game.session 包内 profile 物理拆成独立器官包。

## 一、为什么「万物皆可插拔」走到了头

项目一开始的想法是：所有功能都是插件，全部可插拔。做到现在发现两件事：

1. **内核其实没法插拔。** 身份短卡、内心、记忆、时间、对话面——这些写成插件只是复用了注册总线的形式。真拔掉任何一个，「她」就不成立了。代码其实已经承认了这一点：它们被强制启用、禁止关闭。那就别再叫它们插件。
2. **平台和平台上的能力不是平铺的兄弟，是父子。** 发空间、改签名、发语音、生图，全都长在 OneBot 这具身体上；星露谷长在游戏会话上。OneBot 不在，发空间这个能力就没有意义——但现在它们全部平铺在一个列表里，层级只存在于一个没人消费的 `PlatformId` 字符串里。

所以承认现实：插件不是一个均质列表，是三层。

## 二、三层定义

### 第一层：内核组件（不是插件）

> 一句话：拔掉它，她就不再是她。

| 组件 | 现在穿的插件马甲 | 干什么 |
|---|---|---|
| 身份 | `builtin.identity` | 四张身份短卡 + 每日复盘修订 |
| 内心 | `builtin.inner-life` | 当前内心切片挂载与持久化 |
| 记忆 | `builtin.memory` | 今日新识、网状记忆激活与归档 |
| 时间 | `builtin.time` | 时间感、日程、到期叫醒 |
| 感官目录 | `builtin.senses` | 当前身体与器官的总览挂载 |

规则：

- 编译进主库，强制启用，**不可关闭**（代码已实现，本文档予以正名）。
- 它们实现 `ITracePlugin` 只是复用注册总线（统一挂 facet / callable 的入口），不意味着可拆。
- 文档、界面、目录里都叫「内核组件」，不再叫「内置插件」。

### 第二层：平台（身体 = 连接桥 + 翻译）

> 一句话：把外面的事翻成 Moment，把灵魂的话翻成平台能发的东西。不做决策。

| 平台 | 身体 | 连接 | 备注 |
|---|---|---|---|
| console | 本地文字壳 | 进程内 | **观察窗 + 调试口**：平台身份，不可禁用；不参与滑落计算、不挪激活身体；所有来源的收发都在它这打印一份（运行痕迹，不进对话历史）；只有当轮消息来自 console 时回复才只走 console |
| onebot | QQ | 反向 WS 连 NapCat | 可插拔 |
| game-session | 游戏 | WS 桥，等游戏 mod 连进来 | 可插拔，完全自研 |

平台该干的事：

- 注册 `PlatformHandle`（我是谁、连没连上）与平台适配器（出站怎么发）。
- 平台规矩平台自己带（如 OneBot 的合并发送、输入状态钩子）。
- 会话/连接的建立、维持、断开报告。

平台**不许**干的事：决定说什么、什么时候说。开口内容永远归灵魂。

两个平台的对称：

| | onebot | game-session |
|---|---|---|
| 连接 | 反向 WS 连 NapCat | WS 桥等游戏 mod |
| 翻译 | QQ 消息 ↔ Moment | 游戏事件 ↔ Moment |
| 子级器官 | qq.sticker / qq.status / qq.qzone / qq.tts / qq.imagegen | game.stardew / game.generic |

### 第三层：器官（长在平台上的具体能力）

> 一句话：身体上的一只手、一张嘴；可以独立开关；身体不在，它就休眠。

- `qq.sticker`（表情）、`qq.status`（签名）、`qq.qzone`（空间）、`qq.tts`（语音）、`qq.imagegen`（生图）：隶属 onebot。
- `game.stardew`（星露谷）、`game.generic`（通用游戏）：隶属 game-session。当前以平台包内 profile 的形态存在，**概念上先升格为器官**，物理拆成独立插件包是后续渐进动作。
- 每个器官在 `TraceContributionDescriptorData` / 插件元数据里声明 `PlatformId`，指明自己长在哪具身体上。
- `PlatformId` 为空的器官视为**中枢器官**（直属于灵魂的能力，如将来的网络搜索），不随任何平台休眠。

## 三、生命周期三规则（让层级成为真实约束）

层级不是文档里的图，是运行时的约束：

1. **平台未启用或未连接 → 其器官休眠。** 休眠器官的 Contribution 不进可用目录，不参与工具检索。休眠不是禁用：器官的开关状态保留，平台回来了自动醒。这样她永远不会「身体不在还假装能发空间」。
2. **平台启停联动子级。** 平台启用时，等待中的隶属器官补激活；平台禁用时，隶属器官集体休眠。
3. **列表按平台分组。** 插件界面与状态接口里，器官陈列在自己的平台节点下；内核组件单独一区，不提供开关。

## 四、这张分层图（定稿）

```text
内核(不可插拔,纯中枢,不做平台的事)
└─ 组件:身份 / 内心 / 记忆 / 时间 / 感官目录

平台层(身体 = 连接桥 + 翻译,不做决策)
├─ console        内置保底平台(不可禁用)
├─ onebot         QQ 身体
│   ├─ qq.sticker     表情
│   ├─ qq.status      签名
│   ├─ qq.qzone       空间
│   ├─ qq.tts         语音
│   └─ qq.imagegen    生图
└─ game-session   游戏身体(自研)
    ├─ game.stardew   星露谷(适配器 / 身份槽 / 角色指令 / 安装器)
    └─ game.generic   通用游戏(平台内置兜底档案)
```

## 五、与既有宪法的关系

三个维度各管一件事，互不替代：

- 总纲 §8 的五种 Contribution（moment_source / mounted_facet / callable_nerve / effector / background_service）：**插件提供什么**。
- 总纲 §29 与《平台与感官架构定位》的能力表、身体远近：**路由怎么选**。
- 本文档的三层结构：**插件之间是谁的谁**。

本文档同时正式修订总纲 §25.2 的一句话：「内置身份/内心/时间/记忆/对话仍是 Host 进程内插件，语义上可关」——**修订为：它们是内核组件，语义上与代码上都不可关**。可关的是平台与器官。

## 六、现有插件的归属映射

| 现在 | 归属层 | 动作 |
|---|---|---|
| builtin.identity / inner-life / memory / time / senses | 内核组件 | 仅正名，代码不动 |
| builtin.dialogue | 拆：console 平台（保底）+ 内核残余职责再归位 | 后续整理，概念先定为「console 是平台」 |
| builtin.onebot | 平台（qq） | 已是 Platform 角色，无需动 |
| qq.sticker / qq.status / qq.qzone / qq.tts / qq.imagegen | onebot 的器官 | 已声明 PlatformId，补休眠约束 |
| game.session | **升格为平台**（game） | Role: Organ → Platform，补 PlatformHandle |
| profiles 里的星露谷 / 通用游戏 | game-session 的器官 | 概念升格；星露谷物理拆包以后再说 |

## 七、红线（不许破的规矩）

1. 内核组件不出现在可开关列表，没有任何开关路径。
2. 平台不做决策：不决定说什么，不决定什么时候说。
3. 器官只通过平台注册表（`PlatformAdapters` / `Platforms`）与平台协作，不实例化平台类、不假设平台一定在线——它声明归属，休眠由框架执行。
4. console 是最后的对话面，平台里唯一不可禁用。
5. 器官的启停状态与平台的连接状态是两本账：她「想不想用这只器官」和「这具身体在不在」不许混为一谈。
