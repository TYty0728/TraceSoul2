0.1.58非Windows平台将原始字节采集移入独立快照进程，活Host只传路径并等待结果，避免打开/关闭源数据库文件。快照入口在家目录解析、数据库初始化、模型/插件/网络服务之前返回；只在私有副本进行SQLite backup与校验，不打开源库的SQLite连接。源文件/WAL/回滚日志前后指纹和3次有界尝试、子进程取消、目录保护继续生效；Windows保留现有路径。子进程只返回固定结果码，不把SQLite错误、私密正文或路径回传为网页错误。

新增回归验证活动WAL确实存在、快照包含未checkpoint的已提交行、第二进程退出后WAL/SHM仍存在、原连接可继续提交且重开完整性正常；Linux发布CI执行完整备份专项。更新前校验失败仍拦住交接，页面附上脱敏原因；不因空间恢复而绕过保护。

**既有数据恢复仍须独立验收。** 从仍持有的文件句柄保存缺失日志，保留原始材料和异地加密副本；在副本比较原始对话、旧存档、索引与派生引用。通用恢复工具可能重新引入旧记录或留下引用缺口，结构完整性通过不等于业务资料无损，不能直接替换正式库。程序修复发布与正式停机/恢复分开操作。

副本验收还须逐表对照完整主键索引与实际数据页，检查字段类型和业务引用；SQL扫描能返回的行也可能来自错位的异表数据页。保留原ID、rowid及可正确读取的原记录，依据已保存响应重建的派生资料要单列来源，无法恢复的原始时间字段明确披露，不编造为精确原件。程序兼容检查使用断网、仅挂副本的隔离环境；不能为了测试而启动正式主体。恢复验证与覆盖正式资料是两个授权范围。

## 单份定时与更新保护

按用户最新要求，正常运行默认每周一次，即间隔168小时（间隔可配置），当前存档目录固定只保留1份已验证成品。周期从启用/修改计划或解除更新保护时开始计算，不固定到某个星期几。生成在私有暂存中进行，旧包持续可用；新加密包落盘后重新读取，核对包哈希、解密认证、清单/文件哈希和全部数据库quick_check，再提交新包并清理旧包。新包在完成校验前不出现在可下载列表。任一阶段失败保留旧包，损坏候选及其元数据不作为成品保留。替换期间磁盘会短暂同时存在两份，强制断电可能留下候选；不会先删唯一旧包腾空间。系统时钟回拨也按本次通过校验的编号选择新包。

WebUI安装更新在交给外置更新器之前，强制生成并完整校验存档，即便平时定时关闭也执行；备份失败则不启动更新器、不关闭旧Host。成功后锁定该包，更新后暂停定时和手动替换。用户检查角色内容、设置及插件正常后，在「备份与恢复」点击「确认当前版本正常，解除存档保护」；确认绑定当前版本和保护包编号，重新校验旧包，原包仍保留到下一轮成功替换，计划从确认时重新计时。

保护状态跨重启保留，改计划不能移除保护或更换目录绕过。需要连续安装纠错版本时沿用同一份更新前好包，不用坏版本的当前资料覆盖它。外部更新造成程序版本变化时，也会保护已有旧版本包；无法确认版本的旧成品同样保守锁定。已有多份旧包只在新包验证成功后收敛到1份，不在启动时清理；更换目录留下的旧成品、复制迁移原件和演练目录不属于当前目录的单份轮换清理范围。

这是为更新损坏预留恢复点。数据库能打开、JSON合法不代表内容一定正确，因此不能仅凭新版本启动成功自动解除保护。同版本手工替换程序或外部直接覆盖/删除备份文件无法由版本变化识别；独立更新脚本也不执行WebUI的更新前钩子，应先手动确认已有存档可恢复。

本地验证：专项覆盖密文候选写坏、文件失败留旧、时钟回拨、更新前锁定、重启/计划写入不能绕过保护、内容记录被清空但数据库仍合法、连续纠错、过期确认拒绝与确认后的单份轮换。真实临时Host验证版本变化重启/API保护/确认与替换；UpdateCheck实际走完合成Release下载/摘要/解包后，确认备份失败阻止交接和关闭Host。沿用上轮两真实角色的恢复副本完成加速计划演练，3916文件/11库、保护点及最终恢复校验通过，3912来源文件哈希与写入时间不变；版本变化、时间推进和确认操作均为测试模拟。真实实例未运行，也未启用正式定时。

## 更新后的路径检查和自动迁移

Host启动入口在调用`TraceHome.Resolve`创建目录之前运行`RuntimePathRepair`，因此更新后重启以及普通重启都会检查，检查时尚未打开角色数据库或加载插件；独立Migration工具仍可单独使用路径解析代码。优先采用实际环境变量、home.json及此前迁移记录，合法的外部自定义路径和Docker挂载继续使用；明确新建的实例不会借用其他家目录。

自动处理可确认的错误：运行资料误放在应用目录、更新后配置仍指向已经搬走的位置、遗留plugin-data目录、只剩旧机器路径但有唯一对应本地资料，以及存档成品误放在程序/角色/插件树中。仅查已知目录和最新一份更新器命名的应用备份，不扫描整个磁盘，不混合多代资料。正常目录不会为了统一样式而搬迁。

每次迁移先复制到受限权限暂存目录，核对全量文件、SHA-256和空目录，校验成功后采用目标。**来源目录仍在原路径，既不改名、不删除，也不写重定向标记或修改旧配置**；SQLite主库及WAL/SHM一并复制。目标有不同数据、多个候选、来源仍被占用或变化、链接或目录相互包含时停止，不覆盖、不合并，也不会继续加载一个新建空库。启动检查不包含旧目录清理入口，需新位置实际业务运行、备份与恢复验收后，由用户另行确认清理范围。

迁移结果、复制校验时间、原件清单指纹和旧路径别名保存在家目录`runtime-paths.json`；家目录别名另存应用旁的私有索引，旧启动参数及其子路径可指向新位置，不需要改写原家目录。误放在应用子目录的家目录复制到应用旁`Data`。后续启动仍核对保留原件的指纹，目标正常产生新资料不影响重启；旧目录又被写入、原件或目标丢失则停止自动选择，保留两边供核对。应用和数据混放在同一个根目录而无法可靠区分时停止自动迁移。旧版本更新器本身拒绝的重叠安装布局，仍需先让新版Host成功载入后才能执行自检。

新位置的home.json、存档计划以及常用插件/QQ/语音配置中指向已复制资料的路径字段会同步更新；密钥值、Prompt正文和聊天不做文本替换。改写前的配置原件保存在新家目录`.path-repair-configs/`，位置记入迁移记录。「备份与恢复→资料来源」显示复制来源、目标、旧目录保留和清理待确认。迁移记录、原件及配置备份不进入发布包；保留在资料树内的旧来源也不重复进入后续存档，旧机器路径别名不带进存档包。

本次合成回归覆盖错误位置、WAL/空目录、旧路径原件与配置不变、新目标写入后的旧参数重放、旧目录被写入时阻断、自定义路径、更新备份找回、目标冲突、存档/家目录复制、旧机器路径与配置引用。真实临时Host验证启动时复制迁移、原路径和内容不变，以及后续存档/离线恢复。另以本机现有两角色、插件程序及资料完成两轮加密存档/离线恢复，首包3915文件、11个SQLite逐库quick_check及逐表数量一致；家目录/插件/插件资料三项复制和旧参数再次检查通过。修正后的全源3974文件数量、SHA-256及写入时间一致，未启动真实Soul/模型/QQ/设备，未部署服务器。首次演练暴露只读连接生成6个WAL/SHM、更新7个既有SHM缓存以及tsconfig的JSONC差异，已修复；原主库、事务日志、配置等非SHM既有文件未变，新旁文件保留未清理，详细证据仅保存在本机运行记录。仍待实际业务启动和服务器验收，不以隔离演练代替正式实例验收。

## 首版操作与目录

WebUI → **备份与恢复**。默认定时关闭，间隔168小时（每周一次）、固定保留1份；首次启用或修改间隔后，从保存计划的时间开始计时，也可单独点击「立即存档」。计划由 Host 后台执行，不依赖网页；重启保留最后尝试时间，到期只补一次，失败也等待下个间隔。更新保护期间暂停替换，解除后从确认时重新计时。生成任务在浏览器断开后继续，Host 退出时取消并保留已有成品。

默认位置如下；保存目录可填写相对于家目录的路径或服务器绝对路径。

```text
<家目录>/archive-settings.json       计划与最近结果，不含恢复密钥
<家目录>/archive-recovery.key        实例恢复密钥，单独保存
<家目录>/archives/
  packages/                         加密成品 .tsbackup 与元数据 .tsbackup.json
  work/<随机任务目录>/              私有明文暂存，正常完成/失败后清理
```

存档包内部统一为 `Data/`、`Plugins/`、`plugins_data/`、`Extras/<名称>/`、`AppDefaults/`，以及包含版本/起止时间/文件哈希的 `manifest.json`。运行资料使用启动检查后的有效路径，明确放错位置的目录按上节规则复制迁移。未处于更新保护时可主动修改保存目录，原路径上的旧成品仍保留；单份轮换只作用于当前目录中具有匹配元数据的成品，生成失败不执行旧成品清理。

包采用分块 AES-256-GCM，每份包使用随机盐派生独立密钥，逐块认证并要求认证终止块。恢复密钥不进入包，持久配置/密钥/临时目录限制为运行用户（Windows另含SYSTEM）访问。请另行下载并保管恢复密钥；已有计划的密钥丢失或被替换时拒绝生成新包，不自动换钥。修改目录不改变密钥。

默认收集家目录顶层JSON（不含存档计划）、所有角色及外置当前角色、插件程序和插件数据；包括主库、向量、日终、失败保护及插件SQLite库。普通文件检测复制前后的时间/长度与哈希，JSON另作语法检查；依赖中的tsconfig按JSONC允许注释和尾逗号，保持原字节。SQLite主文件及存在的WAL/回滚日志先复制到私有暂存，前后核对文件集合、长度、写入时间与SHA-256，并核对暂存文件，最多尝试3次；持续变化则失败。只在通过稳定性校验的副本上调用backup API，转换为独立DELETE日志模式并quick_check，不打开源SQLite连接，避免只读WAL连接仍会生成或更新源SHM/WAL的问题（[SQLite WAL说明](https://www.sqlite.org/wal.html)）。当前Soul运行锁及日终队列在收集期间互斥，打包/加密阶段释放；不承诺与第三方独立服务处于完全同一时刻。

不收集控制台登录会话密钥、家目录下的历史备份/更新/dump，跳过调试分支目录、Git/Python缓存、SQLite旁文件及临时文件。附加目录必须明确填写，一行 `名称=绝对路径`，例如分别指定语音服务的 `voices`、`lab/cards` 目录，避免把整个模型环境装进包。缺少来源、变化不停、链接路径、损坏数据库或非法JSON会失败并保留旧成品；未静默忽略错误文件。进程被强制终止时可能留下受限权限的work目录，需要核对任务已结束后再清理。

「校验可恢复性」解密当前成品，核对清单、哈希和数据库完整性，不覆盖运行资料。换机恢复可使用随Host发布的离线入口：

```text
dotnet TraceSoul2.Host.dll --archive-extract <存档.tsbackup> <恢复密钥.key> <尚不存在的目标目录>
```

该入口在家目录解析和所有实时服务初始化之前执行，只在全量验证后产生新目录；目标已存在时拒绝覆盖。恢复副本的 `Data/home.json` 改为相对插件路径，外置当前角色映射为 `_external_current`。原数据和配置不变，不启动Host/QQ/日终/设备；用户核对版本、OneBot和外部服务路径后再自行启动。独立Extras资料需分别放回相应服务。启动恢复副本时将 `TRACESOUL2_HOME` 指向 `<目标目录>/Data`，清除旧 `TRACESOUL2_DATA`、`TRACESOUL2_PLUGINS`、`TRACESOUL2_PLUGINS_DATA` 覆盖，或显式改成新目录，防止仍加载原资料。

电脑目前支持从网页手动下载成品和密钥；电脑自动拉取、百度授权上传尚未接入。包可由外部同步工具复制，但恢复密钥应另行保管。自定义挂载目录需给予容器运行用户读写权限，且必须使用专用目录。

| Soul 人格、身份卡、名字与关系、经历、认知、内心状态、插件启停及插件文档 | `<角色目录>/tracesoul2-brainframe.sqlite3`；身份卡与插件状态有数据库记录，不能只收集 JSON |
| 记忆向量 | `<角色目录>/tracesoul2-vectors.sqlite3`；首版建议一并保存 |
| 模型供应商、用途槽与密钥 | `<角色目录>/llm-providers.json` |
| 角色运行设置 | 角色目录中的 `runtime-settings.json`、`memory-nerve.json`、`life-state.json`、`bodies.json`、`onebot.json` 等存在的文件 |
| 日终进度与失败保护 | `<角色目录>/migration.sqlite3`、`failure-protection.sqlite3` |
| 身体与感官设置 | `<角色目录>/wxxz/`，包括已保存的本人声纹和语音设置；其他设置以实际目录为准 |
| 外部插件持久配置和资源 | `<插件数据目录>/<包名>/config.json` 及同目录资源、索引和数据库；如共用表情库、游戏会话库 |
| 插件程序与自定义内容 | `<插件代码目录>/`；官方包可按版本重装，自定义插件和本地改动应保存，不能只记包名 |
| 初始身份模板与程序默认规则 | `identity_cards.json` 可在角色目录覆盖程序自带模板；实际身份卡还在主库。`src/TraceSoul2/Prompts/` 等规则随程序发布，应记录 Host 和插件版本 |

正常家目录布局中角色目录是 `<家目录>/souls/<id>/`。旧 `TRACESOUL2_DATA` 可以把当前角色指向其他目录，存档清单应记录解析后的实际来源。仅有旧DATA变量、没有标准角色根目录时，只收集明确指定的当前角色，避免递归收集其父目录中的程序、备份或其他资料。标准 Docker 部署将家目录、插件代码、插件数据分别放在宿主机 `runtime/Data/`、`runtime/Plugins/`、`runtime/plugins_data/`；这不是对用户服务器实际路径的核验。

声音或硬件服务可能另有持久资料，不能因 Host 已存服务地址就认为音色也被备份。`Tools/LocalVoice/README.md` 中的 `voices/`、`lab/cards/`、`access.json` 属于独立语音服务运行目录；开发板网络配对文件也属于独立桥。只有将这些服务明确纳入备份范围，才能承诺恢复对应声音或硬件连接。模型权重、虚拟环境和可重新下载的依赖可另记版本。

## 现有能力与限制

- `Tools/Host/DebugBranchService.cs` 已用 `VACUUM INTO` 复制主库、向量库和日终库，可以参考数据库副本的实现；它是调试分支功能，不是完整实例存档。
- `scripts/Export-DockerRuntime.ps1` 配合 `docs/DOCKER.md` 用于**先停止 Host 后**迁移目录，还会修改导出副本的路径配置；不能直接当成在线定时备份器。
- WebUI 的更新备份主要保存旧程序和被替换的官方插件，不能代替本次新增的完整定时存档入口。
- SQLite 主文件可能还有未合并的 WAL 写入。在线存档应使用 [SQLite 在线备份或 VACUUM INTO](https://www.sqlite.org/backup.html) 生成可独立恢复的数据库副本，不能只复制主文件或忽略 WAL。逐个数据库有效也不等于所有数据库、JSON、插件资源处于同一时刻；实现时仍需协调写入或明确一致性边界。

## 后续目的地

先在服务器生成一次经过验证的完整存档，再把同一个成品交给不同目的地，避免每种上传方式各自收集一套数据。

| 目的地 | 用法与边界 |
|---|---|
| 电脑上的专用目录 | 作为离开服务器的副本。手动可从网页下载；定时落到电脑目录需要电脑端拉取或同步程序，电脑离线时保留待传存档 |
| 百度网盘 | 作为另一个远端目的地。建议上传前加密；正式接入前核对当前账号授权、上传与凭据续期方式。尚未连接账号或验证上传 |
| 服务器自定义目录 | 作为持久存档目录或传输暂存。应放在更新和缓存清理之外；如果与源数据同机同盘，不能覆盖服务器整机或磁盘丢失 |

首版已实现完整存档、每周定时生成、持久保存目录、单份轮换、立即下载、结果记录与恢复预检，后续接电脑自动拉取和百度上传。届时生成成功与各目的地传输成功应分别显示；远端失败时保留成品并允许重传。

存档应带创建时间、程序和插件版本、角色范围、相对目录映射、文件清单和校验值。完整包包含私密对话和凭据时，应提供可靠加密，解密口令或密钥由用户另行保管。存档目录和临时目录必须排除出输入，防止递归打包旧备份；默认跳过下载缓存、更新包、调试 dump 和可重建依赖，对未纳入的外部资源明确列出。

验证：Host构建、完整ChatCheck与Prompt布局、`--backups`专项、备份/WXXZ页面、真实临时Host鉴权/生成/下载/预检/离线CLI及发布隐私回归通过。专项覆盖WAL写入恢复、插件/附加资源、密钥/篡改/截断/尾随数据、路径越界、重启计划、并发去重、单份轮换和失败保留；自动回归使用临时合成资料，真实角色的隔离演练结果见前文，没有启动正式实例或真实模型。服务器真实数据恢复和浏览器现场点击尚未验收。
