# 按范围读取记忆

2026-11-03。本地第一版，接入当前统一Agent；不恢复旧记忆定位子代理，不增加固定模型阶段。用户要求“昨天是否洗头”先找昨天，“喜欢吃什么”先找偏好主题。

## 后续设计：让数据库可像项目目录一样浏览

同日用户用编码Agent读取工程作类比，提出先看目录、再决定去哪里找。现有域/维度、LifeTag定义和路由、日期索引、事件/认知及原件引用可以提供这种导航。数据保留在SQLite，向Agent提供虚拟目录视图，同一记录可被多个入口引用。

后续澄清：目录是按需可用的能力，不是每轮对话必须阅读的入口，更不是固定“查目录→检索→回答”流程。普通相处继续依靠身份、当前状态、对话与已有认知；同一Agent需要查证或行动时才选择工具，已知范围可直接读取，不要求先走目录。能力简表用于让主体知道自己能做什么，详细操作说明拟在选择能力后按需展开。当前代码尚未实现这类按需展开：Agent每轮仍注入记忆读取说明和完整可用工具目录，但并未强制每轮调用工具。

电脑操作与plugins不是二选一：Agent决定是否行动，工具定义可调用动作，插件负责交付实现、连接设备和管理生命周期。电脑操作可由插件提供屏幕观察、窗口/浏览器操作和文件访问等工具；记忆导航仍直接使用内核记忆接口，无须绕经桌面点击数据库。需要持续接收电脑环境输入时，再沿现有平台/感官边界接入，同一Soul保持唯一权威状态。这里只澄清职责与按需使用原则，尚未实现电脑插件或决定其具体能力范围。

现阶段memory.topics按语义返回最多12个主题候选；memory.recall执行已经选择的范围；memory.source读取已知ID原件。还缺可逐层浏览和分页的目录入口，不能将本版范围过滤描述为已经拥有完整目录探索能力。

拟增加memory.catalog：按主题或日期列出当前可见节点，提供稳定ID、名称、定义、下级入口、记录数量/覆盖范围和分页游标。节点摘要应描述目录里有什么、适用什么问题；不在顶层塞入全部正文。日期与主题是并列导航视图，交叉后仍调用当前范围读取。提供范围内清单浏览，使Agent可以在关键词无匹配时检查该范围的其它表述；默认不跳出原范围。

目录由真实表和关系生成，先限制受众再统计数量及生成摘要，不能通过目录泄漏私密内容。主题归属继续在复盘时根据语义复用或生长，目录条目引用原件和认知ID，不复制内容形成多个独立版本。首次实现可只用已有固定域/维度和可生长主题，任意深度主题父子关系需要单独设计，不能假装现库已存在。

类比工程：目录/模块说明对应主题与日期导航；范围内搜索对应限定召回；打开文件对应读切片/原件；追踪引用对应追溯认知证据。读取导航和写入归类分别负责找得到、放得对。发生时间与记录时间分离仍是独立的数据语义问题，目录不能凭空补齐未保存的发生日期。

此节为后续方案，尚未新增catalog工具或修改数据库结构；本版已落地的范围读取见下文。

## 职责与主链

```text
当前输入 + 主题候选 + 日期基准 + 既有状态/榜单背景
    → 同一Agent判断问题类型，选择日期和/或主题
    → memory.recall 校验参数、规范化范围
    → 日期 ∩ 主题 ∩ 受众权限限定候选
    → 范围内排序，返回候选和原件引用
    → Agent结合原话回答；需要全文时 memory.source 分页读取
```

模型负责理解问题、选择主题与范围；程序负责过滤、日期边界和空结果。程序不根据正文里偶然出现“昨天”强制分类，不把关键词命中当作理解，也不让语义相似度越过已选范围。语义选择质量仍需真实模型验证。

普通新消息进入Agent前，停止全历史事件的自动语义预激活，保留主题导航和当前认知的轻量预读；后者不带事件、日复盘或原件，避免普通相处突然失去已有理解。当前身份、真实对话窗口、runtime和榜单继续作为背景，明确不冒充本次范围查询的结果。后台自主活动继续沿用原预激活。已有明确原话充分时可以直接引用；缺少依据时由同一Agent发起读取，不要求所有闲聊都查库。

## 工具契约

`memory.recall` 沿用字符串参数；query必填，1～500字符。

| 参数 | 用途 |
|---|---|
| kind | events：事件及同期原文；cognitions：当前认知与依据；sources：原始记录；auto：兼容综合查询 |
| tags | 0～3个现有主题名组成的JSON数组字符串，按语义从候选或memory.topics中选择 |
| period | today、yesterday、day_before_yesterday、this_week、last_week、this_month、last_month、this_year、last_year |
| date_start / date_end | 明确起止日期，yyyy-MM-dd，两个端点日期均包含；单日填相同日期 |
| day_basis | calendar默认自然日，或memory归档记忆日；必须与日期一起提供 |

period与显式日期互斥；显式日期须成对、有效、先后正确。非法范围返回failed，不能静默忽略或改成全库查询。auto带日期时自动转events；未提供新字段的旧query/tags调用保留综合读取兼容。具体日期问题的Agent说明要求提供日期参数，不能保证真实模型永不遗漏。

自然语言“昨天”按输入原件的时间戳和固定北京时间+08:00计算，跨同轮续推、服务器时区或排队延迟保持一致；无原件时间才使用当前时间。calendar在00:00切日，memory沿用MemoryDayLogic的04:00切日；周从周一开始。内部统一为 `[start, end)`，不漏最后一毫秒，也不把下一天零点混进来。归档调度没有改变。

例如，在2026-11-03 01:30 +08:00提问：calendar的昨天是11月2日00:00至11月3日00:00；memory的昨天是11月1日04:00至11月2日04:00。含糊的“那几天”应先澄清，不能猜一个日期。

典型调用参数：

```json
{"query":"洗头","kind":"events","period":"yesterday"}
{"query":"洗头","kind":"events","period":"yesterday","tags":"[\"日常清洁\"]"}
{"query":"喜欢吃什么","kind":"cognitions","tags":"[\"口味偏好\"]"}
{"query":"关于洗头的原话","kind":"sources","date_start":"2026-11-02","date_end":"2026-11-02"}
```

## 各类材料的时间与来源

- 事件按已保存的EventIndex.TimeUnixMs锚点筛选，不能按EventEntry.CreatedUnixMs的复盘写入时间筛选。再在范围内用现有BGE排序；未建向量的切片允许词项匹配，候选范围不变。
- 原件按Moment.CreatedUnixMs记录时间限定，包含已归档和未形成切片的对话、感知、工具观察。先在数据库按会话、时间和可见性过滤，再取最近窗口，旧日期不会被最新记录挤掉。原文目前是词项匹配，不宣称已实现原文BGE索引。
- 有主题限制时，原件只来自所选主题事件的来源关联；未归类原文不会因为词相似就进入该主题。公开环境仅读取当前环境的公开原件，不能借日期查询绕过私密限制。
- cognitions读取当前有效认知及依据，不混入事件或主观日复盘文本。禁止它与日期范围组合：当前认知不能冒充过去某天的认识，也不能用认知更新时间证明某天发生了某事。查过去事实应读events/sources。
- 工具观察遵守同一日期范围；限定查询不追加旧的全范围工具观察召回。近期观察动态段明确标为背景。memory.source继续检查受众，全文带自身记录来源和时间语义；显式读取原件不等于其所有内容都发生在提问日期。

重要边界：现行日复盘的事件锚点通常取首条来源的记录时间，没有独立的“真实发生时间”解析。今天才说“前天洗了头”，不一定能通过前天的时间过滤找到；返回文字明确区分记录时间和发生时间，不借这次改动伪造历史日期。跨日持续事件也受已有锚点粒度限制。下一阶段如要覆盖此类回顾，需为事件增加独立发生时间区间、来源/确定性，以及事件证据对应关系，再设计历史补全；本版不自动重写旧库。

## 返回与预算

结果始终带本次规范化范围、读取类型和所选主题。候选附索引/原件ID、记录或索引时间、来源与证据类型；长原件通过memory.source继续分页。范围内空结果返回empty，明确“没有记录不等于没有发生”，不自动放宽日期、主题或受众。

事件和原件各最多检查范围内最近2000条，输出各最多6条节选；超限明确报告覆盖不完整，提示缩小日期或主题。现阶段不支持浏览式翻页扫描整个候选集合，原件全文分页仍可用。证据读取按256条批次调用既有接口，避免接口上限静默丢失可见来源。原auto综合查询沿用既有预算。

## 实现与验证

- `MemoryReadScope`：日期契约、解析及Agent动态说明。
- `ScopedMemoryReadLogic`：读取类型路由、范围过滤、排序、来源与覆盖报告。
- `KernelLogic`：实际memory.recall分派、普通新消息停止先全库预激活。
- `SqliteMemoryManager.GetScopedMemorySources`：范围先于LIMIT的原件查询，没有新增数据库表或共享接口必需成员。

`ChatCheck --memory-scope` 覆盖自然日/记忆日、闰日/周月/左右边界、非法范围、日期与主题交集、认知/原文路径、空结果、公开隔离、实际Kernel只向检索器传入限定候选、2000条覆盖提示，以及跨256条证据批次。`--memory-routing-audit` 已改为带period的实际调用，可复核原来跨日候选变成仅昨日候选。

测试使用模拟Agent、可观测检索器和临时数据库；能证明执行边界，不能证明真实模型总会选对日期、主题或理解原文。Host/ChatCheck构建、Agent专项、认知图回归、完整ChatCheck与Prompt布局均通过。完整回归确认保留当前认知背景预读，并修正日志故障测试夹具被自动发现的问题。本地尚未发布部署；正式数据、睡眠复盘流程和历史记录未改。
