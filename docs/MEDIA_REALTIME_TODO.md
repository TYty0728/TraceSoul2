## 状态与约束

本文件是实施清单，未勾选项目不代表已经实现。QQ AV 桥来自社区项目，Linux QQ/AVSDK 版本兼容、主动拨出和视频能力尚未实机验证。不向真人发送自动验收消息。已有认知网修改保持原样。

用户已确认目标为 **Linux 服务器上的 Docker**。本机没有该服务器的容器连接，因此 QQ 前置检查仅提供脚本，未对远端执行。当前代码可在没有模型密钥的情况下完成全部基础回归。

### 当前交付与验证

- `ExternalPlugins/MediaUnderstanding/`：`media.source.inspect` 识别来源；`media.video.analyze` 受限下载、校验、抽帧、读取平台字幕并调用多模态槽。没有字幕时不会推测对白，尚不直接识别音轨。
- `ExternalPlugins/RealtimeCall/`：鉴权 WebSocket、最终转写入口、客户端 TTS 输出、时长/播放回执和中断语义；协议和 Docker 桥接说明见该目录 README。
- `src/TraceSoul2/Data/MediaRealtimeData.cs`：共享纯数据，加入 PluginApi 1.4.0 显式源清单；旧版 Host 不能直接安装新插件。
- `scripts/probe_qq_call_bridge.py`：在 QQ 容器内运行的只读诊断，不复制上游桥源码、不安装或修改 QQ。检查通过也不声称通话已验证。
- `Tools/MediaRealtimeCheck`：86 项检查通过，包含来源解析、抽帧采样、字幕解析、临时资源清理、无 shell 参数传递、输出上限/进程超时、独立回环 WebSocket 鉴权与限制、会话隔离、最终转写、服务端推送、完整/部分播放记忆、打断和断连清理。
- Python 4 项诊断检查通过：回环地址边界、脱敏、缺令牌状态、拒绝重定向。
- Host、新两个插件与现有 GameSession/QqTts/QqStatus/QqQzone/QqImageGen 构建通过；完整 ChatCheck 与 Prompt 布局回归通过。
- 当前外部验证缺口：本机没有 `yt-dlp`/FFmpeg，也没有目标 Linux QQ 容器连接，因此尚未跑真实 B站/抖音链接、真实模型、QQ 来电/音频和 Unity 麦克风。QQ/Unity 仍需音频网关把 ASR/TTS 接到已完成的转写协议；GPT Live、主动拨出和视频尚未实现。
