## 2026-10-21 直接选择最高分

用户明确要按评分直接选最高分。QQ与WXXZ共用本轮`ExpressionLibrary.MatchAsync`评分：所有图片参加排名，不设最低分或用途准入门槛；不再因弱信号、用途缺图或分数为零而跳过。相同分数按资产ID稳定排序，不随机。

有正文且图库含用途标注时，所有图片按`0.75×用途分+0.25×心情分`统一排序；没有用途标注或仅有感受时按心情分。用途分取本图标签与正文释义的最高相关分；更接近排除样例的标签使用负的相似度差降低分数。原`requires_intent`不再把最终回复或待机图候选剔除；待机仍用已有状态标签评分，不额外请求模型，用途不符时减分而非禁止参与，即使只有专用图或最高分为负也会选择最高分。

共享评分器与两端交付均在发送前验证图片。开发板与QQ统一调用PluginApi `ExpressionSelection.ReadHighest`，失效时只按本轮分数顺位选择；开发板实体准备/说话帧复用同一已验证图片，网页投影记录实际选择的ID，不另选通用状态图或QQ默认face补位。正文与表情沿用原会话合并发送；取消/目标边界与发送失败未知不重发的规则保留。空库、全图失效或模型服务失败如实报告，开发板保留文字/声音但不伪造评分图，网页也不拿待机图代替本轮图。WebUI预览与实际选图采用同一排名，移除阈值控件；旧`threshold`/`semantic_threshold`配置保留但忽略。QQ3.1.2/PluginApi1.16.0与Host一同更新。

## 已实现的评分路径

Host的`ExpressionLibrary`拥有图库，插件服务通过`IExpressionLibrary`访问。停用QQ插件不会停用板端图库。仍读取`qq-sticker/emojis/<persona>/emoji_index.json`和原图，不复制用户图片进源码；包内默认库先读，持久库后读，同名文件按persona顺序覆盖。旧标签及描述保留，不把“摆烂”等生硬改成某个规范词。

1. 本地BGE分别编码42个标签、每张图的旧标签与描述，生成42维标签评分档案。这里理解的是索引描述，**没有新增视觉模型重新识图**。
2. 最终表达确定后，Kernel只匹配一次：输入Soul实际回复及当前受众允许看到的感受摘要，不输入完整人格、历史或用户原话。两者都有时向量按正文0.7/感受0.3合成；只有一项时使用该项。
3. 每个标签先算余弦相似度，以本组相似度中位数为基线，计算`max(0,(similarity-median)/max(0.05,1-median))`。该分数是相对语义匹配分，不是情绪概率或说话人诊断。
4. 取当前表达前n个正分标签，默认n=4，可配置1～42；与图片完整42维评分向量做余弦匹配。结合上述用途分后按分数降序、资产ID稳定打破并列，直接选择最高分可用图；没有正分标签时心情分为零，仍参与整体排名。旧阈值与`recent_avoid_count`不改变选择。
5. 同一最终表达的结果放在本轮Workspace。QQ与WXXZ读取同一结果，各自检查原会话和身体；新表达开始先清空旧结果，异常也不会复用上一轮选择。

图片原标签与规范词精确一致时该标签设为1；可以在对应图片索引的`tag_scores`对象里显式覆盖任意规范词的0～1分数，例如`"tag_scores":{"开心":0.9,"不安":0}`。未知标签或非法分数拒绝加载，新库验证失败保留旧库。第一次或模型版本变化时重建内存档案，后续仅编码当前表达；不保存私人查询，也不增加LLM/JEV调用。
