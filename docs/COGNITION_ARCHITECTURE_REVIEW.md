状态：源码审查与接入建议，尚未实施新的认知网。用户明确的方向是两部分基础数据：认知、记忆、人格等构成的完整拼图，以及当时维持的内心 runtime；当前行为与被召回的拼图片段共同参与下一步决定。本文件据此区分已有实现和待实现连接，不恢复固定「心智 → 表达」模型阶段。

## 两部分数据与一次运行

长期拼图记录经历、对经历形成的理解，以及较稳定的自我、他者、关系和人格。它可以包含不同类型的节点、索引与摘要，不要求全部塞进同一张表。事实、理解和人格各有语义：发生过什么不因理解改变而被覆盖，理解允许被新证据修订。

内心 runtime 记录此刻的感受、注意、关系视角和当前活动，并跨轮延续。runtime 可以持久化；两部分的区别在于内容的生命周期和用途，而不是数据库与内存的区别。当前实现还将生活状态、定时安排和设备执行账本分开保存，不能把 InnerRuntimeRecord 当成全部运行态。

建议的运行关系：

```text
当前事件 / 行动反馈 + 上一刻 runtime
                    ↓ 形成当前关注与检索线索
长期拼图 → 相关经历、认知、身份片段、反证与来源
                    ↓
           Agent 的本轮工作上下文
                    ↓
             回应 / 行动 / 等待
                    ↓
          实际反馈 → 下一刻 runtime
                    └→ 经历记录 → 后台整理 → 长期拼图
```

本轮工作上下文是两部分数据与当前输入的临时组合，不新增一个独立人格或必须调用的模型岗位。稳定身份基础可以常驻上下文，较细的经历和理解按需召回；资料充分时继续保持一次生成。后台整理负责长期更新，也不必被拟人化成另一个 Agent。

## 建议的接入顺序

1. 定义拼图片段的来源、有效范围、证据和修订关系；优先修复逐条证据归属，避免建立错误的关联。
2. 认知与事件记忆独立召回。当前事件、有效注意、当前活动与行动结果共同提供线索；无事件命中时仍能找到已有理解。
3. 从命中的片段有限扩展到依据、相关理解和反证，在严格预算内输出本轮上下文。runtime 影响关注，不把不符合当前情绪的证据直接排除。
4. 更新 runtime 时可保留相关片段引用，允许关注延续、切换和失活；明确的约定继续由调度系统维护，设备执行状态由真实回执维护。
5. 长期整理再根据真实经历修订认知和身份。想到某件事、计划某个动作以及实际完成动作分别记录；不能让模型重复自己的猜想就增加事实证据。

建议验收场景：关闭短期聊天历史后仍能按证据召回；有认知无事件时正常工作；当前关注能改变召回但不屏蔽反证；失败/未完成动作不成为已完成经历；短期情绪不直接改写稳定人格；重启后恢复 runtime 并重新核对外部执行状态。
