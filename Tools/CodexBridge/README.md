# Codex 本地文本模型桥接（实验）

目标是替代 TraceSoul 主聊天及每日复盘的文本模型。当前提供兼容的
`GET /v1/models`、`POST /v1/chat/completions`，通过官方 `codex exec`
运行独立任务。Host 新增「Codex 本地桥接（实验）」模板，现有主模型及
复盘槽均可选择它。2026-10-28已按用户要求在私有实例配置通用供应商并切换主聊天/复盘；实际地址、密钥和SSH配置只保存在仓库外运行配置中。下方早期试验记录保留其当时状态。

## 启动

需要 Python 3.11+、已登录的 Codex CLI，以及支持 `--ignore-user-config`、
`--ephemeral`、`--no-daemon` 的版本。开发核对版本为 0.165.0-alpha.1.2。
先用 `codex login status` 检查认证；不要复制登录令牌到供应商 API Key。

在启动进程的环境变量中设置 `TRACESOUL_CODEX_BRIDGE_TOKEN`，使用至少32字符
的独立随机密钥。密钥只用于 TraceSoul 到桥接的认证，不是 OpenAI API Key。

```powershell
python Tools/CodexBridge/bridge.py --model <已验证可用的模型ID> --state-dir <源码仓库外的私有状态目录>
```

桥接只监听 `127.0.0.1:5091`。供应商地址为 `http://127.0.0.1:5091/v1`，
API Key 填上述桥接密钥，模型填启动参数允许的模型。请求超时建议600秒，
桥接子进程上限540秒。复盘槽统一使用600秒，聊天槽仍使用原有配置。
模型列表仅报告配置项，不代表账号已获得模型权限。
服务器上的 Host 需通过认证私有隧道连接电脑，不能把服务器自身的127.0.0.1
当作电脑。`service.py`负责桥接及SSH隧道子进程监护，`tunnel.py`复用现有回环隧道传输。私有实例已配置Windows登录启动任务。

## 接口边界

- 仅支持非流式文本和 `json_object`；图片、音视频、函数工具和 JSON Schema
  返回明确错误。现有心智的文字 JSON 行动仍交由 TraceSoul 执行。
- system/developer 内容按顺序拼入本次模型指令；user/assistant 历史按原顺序
  编码为带角色的会话材料。这是适配，不等价于原生 Chat Completions 角色通道，
  需真实角色一致性与业务输出验收。
- 每次使用临时工作目录，忽略用户配置、项目说明，禁用shell、应用、远程插件及
  网页搜索，使用只读沙箱。不会续用此开发聊天或让模型直接写主体数据库。
  不把这视作任意恶意输入的完整隔离保证。
- temperature、top_p、max_tokens 等现有客户端参数不映射为 CLI 能力；本桥接
  按模型默认生成，仍由原业务契约校验输出。不会伪造 token 使用统计。
- 默认单并发，`--concurrency`可设置1～8路，忙时429；并发请求的输入哈希在SQLite事务中原子预订，避免重复启动同一任务。同输入成功结果缓存10分钟，失败冷却60秒，中断的running等待子进程上限加60秒（当前10分钟），
  缓存跨进程重开保留。不能保证任何故障时刻都只推理一次；超时后已经发生的
  上游消耗无法撤回。业务检查点和提交幂等仍由 TraceSoul 管理。
- SQLite保存输入哈希、状态及结果，不保存原始请求或凭据；结果可能含私人内容，
  状态目录按角色数据保护。过期记录在下次接受新工作时删除，不承诺安全擦除。
- CLI失败、超时、空响应、未确认turn完成及非法JSON都返回失败，不自动修稿。
  提供商重试期间由冷却抑制立即重复调用。复盘层整轮最多补试2次，冷却5/10分钟，并有首次故障起30分钟的补试派发窗口；耗尽后暂停等手动恢复。主模型备用保持原行为。

2026-10-30：上述540秒推理与更长running保护源码已随0.1.82发布，尚未同步到私有部署。更新服务器不会自动更新电脑上的桥接，部署仍需避开在途任务。

## 私有部署与进程监护

`service.py --config <仓库外配置文件>`使用以下私有字段：`port`、`token`、
`model`、`codex`（可执行文件）、`concurrency`、`state_dir`、`ssh_config`，以及
可选`python_path`（Paramiko安装目录）。配置文件、SSH凭据、日志、任务状态和
服务器供应商备份必须保存在仓库外受限目录。不要提交已填写配置。

服务会监护桥接与隧道子进程，每10秒检查一次，子进程退出后重新启动；SSH隧道仅
在服务器及容器回环地址监听。状态目录中的`stop`文件用于停止服务，重新启动前需
移除该文件。登录启动使用当前用户身份，从该用户的Codex登录状态取得认证，不向
服务器复制Codex登录凭据。电脑须开机、已登录且联网；休眠/关机时通道不可用。

## 2026-10-30 桌面版本目录失效修复

私有桥接在10:16续做29日复盘时约3秒返回`bridge_internal_error`。本地监督进程与SSH隧道仍存活，但配置固定的桌面版本目录中的CLI已不存在；现用CLI及ChatGPT登录正常，任务未进入模型输出阶段。原桥接将进程启动异常统一隐藏为HTTP500，模型列表仅验证HTTP服务存活，不能证明推理可用。

`CodexRunner`现在每次请求检查可执行文件。明确指向当前用户桌面安装目录的旧版本路径失效时，仅在该安装根目录的版本子目录内寻找现存CLI；不缓存解析结果，长驻进程无需刷新PATH即可应对后续目录替换。其他手动指定的安装路径保持固定，不悄悄切换安装来源。缺失或无法启动分别返回503及`codex_executable_not_found`/`codex_launch_failed`；未知错误只记录异常类型，不打印请求、凭据、路径或异常正文。

9项离线测试通过，新增同一Runner连续两次桌面版本替换后的完整调用、固定路径失效拒绝、安装完全缺失及启动错误脱敏。私有桥接已在维护租约下备份替换并由原监督进程重启桥接子进程，隧道和服务器Host保持；确认无迁移/更新子进程和活跃桥接任务，维护租约已释放，模型槽及失败保护保持。服务器端鉴权模型列表检查通过；服务器命名空间经原隧道调用gpt-6-astra的真实合成JSON请求通过，耗时117.15秒；仅为连通与基本输出验收，不代表整日复盘已成功。未恢复日构建或将测试写回角色。
